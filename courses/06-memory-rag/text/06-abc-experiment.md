# 进阶实作：20 题、三组检索与重排对照

## 原题与实验边界

原进阶页要求：同一份 20 题，A 纯向量、B 加 BM25 并融合、C 再重排，保存前五条证据与答案，对比 Recall@5、命中率、延迟和成本。本章提供三组的完整实现、参考结果和判断方法。

入门运行使用字符计数向量与证据摘录；它是可离线检查的算法基线，不叫语义模型。完整代码也支持已有 Ollama embedding 模型和真实生成。两种模式分别记录，不能拿字符相似性成绩声称神经检索有效。

## 三组只改变哪一处

所有组用同一份虚构资料、用户身份、20 题、候选数和输出数量。

- A：向量余弦检索，取候选前 8，再给出前 5。
- B：保留 A，增加 BM25 字词检索，两路用 RRF 融合，取候选前 8，再给前 5。
- C：复用 B 的候选，对“问题＋正文”重新打分，再取前 5。

BM25 根据词频、文档长度及词在资料中的普遍程度评分。此处中文用单字分词，公式真实但分词较简单；没有把字数重叠直接叫 BM25。RRF 合并的是名次，不直接相加不可比较的分数。

C 的 pair_score 是公开的规则重排器：奖励题目意图和正文条件匹配。它不读取 gold、答案 ID 或题目序号。规则根据公开开发资料设计，不能证明陌生问题上的效果。神经 reranker 可替换此函数，但需另配模型、资源和新测试集。

## 如何解释结果，而不是追求全绿

本组公开样例 A/B/C 的平均 Recall@5 都为 1，A 的 MRR 约 0.972，B/C 为 1。说明正确证据本来就在前五，混合让部分首个相关项更靠前；规则重排在这些题上没有额外平均收益。不能为了展示 C 有用而删掉不改善的题。

更重要的是，两条应无结果的题中只有一条保持空结果：访问 Bob 私有资料被挡住；“火星天气”可能因“天”等常用字匹配到无关资料。它是教学基线的一项实际失败。检索阈值、字词分词和证据充分性都可能影响拒答，不能把“返回了文段”当“已经回答问题”。参考人工答案应是“资料不足，无法回答火星天气”。

排错参考：先打印该题候选，确定不存在天文资料；再增加一个与排序分开的证据充分性判断，要求模型或受控规则明确能否支持问题。不能只对“火星天气”写特判而宣称解决未知问题。改后另外加入没看过的天气/天数问题，检查拒答是否误伤“付款后几天收到发票”。

重排只能调整候选。若正确文段没进候选，C 也无法凭空添加。因此报告同时保留 candidate_recall 与最终 recall。权限先过滤，不能让重排器读到 Bob 私有资料后才在最终答案遮住。

## 接入真实 embedding 与生成

先运行 `ollama list` 查看已有模型。若没有 embedding 模型，下面是明确的额外下载步骤，首次执行约下载 622MB，需 Ollama 0.11.10 或更新版本，可先用 `ollama --version` 检查；模型名只用于本地实验，不是 Python 包名：

```bash
# 下载本行指定的模型；已有且未更新时无需重复下载。
ollama pull embeddinggemma
# 运行 courses/06-memory-rag/examples/rerank_experiment.py，按本行参数完成当前案例并核对输出。
.venv/bin/python courses/06-memory-rag/examples/rerank_experiment.py --embedding-model embeddinggemma > /tmp/course6-abc-embedding.json
```

程序调用本机 `/api/embed`。A/B/C 的其他设置保持相同；不同模型的余弦分布不同，0.25 只是起始阈值，需要用开发题校准。不要比较两组时顺便换切分、题集和生成提示词。

已有 gemma4:e4b 且完成前一步后，可加入真实生成：

```bash
# 运行 courses/06-memory-rag/examples/rerank_experiment.py，按本行参数完成当前案例并核对输出；--live 会进入真实服务路径，需先满足本章环境要求。
.venv/bin/python courses/06-memory-rag/examples/rerank_experiment.py --embedding-model embeddinggemma --live > /tmp/course6-abc-live.json
```

最多为 60 行分别生成，可能耗时较长；先用[综合助手的单题模式](03-workshop.md)确认服务能响应。每个生成结果保留逐条引用，标 NEEDS_REVIEW，按主体、条件、数字、否定、例外核对。调用本地模型没有外部模型 API 账单，但仍占 CPU/GPU、电力、内存与时间；报告不虚构美元费用。模型缺失时应报告请求失败，而不是回退到字符向量假装真实 embedding 成功。

## 课末练习及完整参考判断

请提交原始结果 JSON、每组指标，以及至少一条结果改善、不变或失败的原因分析。再做一次只改变 candidate_k 的实验，保存结果。通过这些比较，区分召回、重排和生成各自影响什么；没有收益也照实记录。

完整答案可直接核对上方参考 JSON：同一题 B 与 C 的 candidates 必须一致；C.selected 只能来自 candidates；三组的输入和 gold 相同；60 行完整，未知和私有题不并入普通 Recall 均值。若报告说“C 全面胜出”，与参考数据不符。

迁移题：自己补两道未参与设计的问法，先标来源再运行。把候选数减为 1，观察正确证据一旦丢掉，重排是否仍能恢复；答案是不能。再把 C 的排序临时反过来，应能在逐题差异中看出回退。一个方法没有提升时保留 B 是合理选择。

验收分两层：实验完成看对照公平、输出齐全、指标正确；系统质量看引用与拒答是否可靠。前者通过不代表后者已经适合上线。两天后不看代码解释 BM25、RRF、reranker 各在哪一步，一周后换一套小资料重建题集。
