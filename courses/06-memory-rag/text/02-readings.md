# 第六课必修及两条进阶支线

## 四份基础必读

LangChain Retrieval 把 loader、splitter、embedding、vector store、retriever 分开：更换某个组件不应改变其他组件的契约。先做固定的两步检索再生成，延迟和失败更容易预测；只有确实需要运行时判断才改成 Agentic。

LlamaIndex 的 Document 是原始资料，Node 是可索引片段，Index 组织查找结构，Retriever 返回候选，Response Synthesizer 依据候选生成答案。Query Engine 组合检索与回答，Router 选择路径。建立索引不是训练模型，删文档也不会自动改变模型参数。

Chroma getting started 展示了一次完整操作：创建 client 和 collection，添加带 ID 的资料，再用 query 查询并读取结果。可以自己提供 embeddings，也可配置 embedding function。metadata 保存来源与过滤条件；业务权限必须来自可信身份。同时记下存储目录和需要下载的模型，之后才方便重跑。

LangGraph Agentic RAG 把检索做成工具，模型选择是否使用，随后检查文档相关性；不相关时改写问题再检索，相关时生成。给每个循环设置上限，把“没有新证据”作为停止理由，不能让相关性评分器的自信替代事实。

## 进阶 RAG：指标与实验设计

Recall@k = 前 k 条找回的相关片段数 / 全部已标相关片段数；Hit@k 只看是否至少命中一条；MRR 是每题第一条相关结果排名倒数的平均。nDCG 还能考虑分级相关度与位置。若资料标注不完整，指标会把实际相关结果误判为不相关，先人工检查标注。

Faithfulness 检查回答是否被给定证据支持，不等于证据本身在现实世界永远正确。Answer relevance 检查是否回答问题；citation correctness 检查引用能否支持相应断言。三者需要分开。

原进阶页要求固定小数据集，对比 A 纯向量、B 混合、C 混合加重排。每次只加一个变量，记录检索、答案、延迟、成本，保留失败题。候选数 k 变大可能增加召回，也会增加噪声和上下文费用。

## Contextual Retrieval、混合搜索与重排

片段脱离全文后可能不知道“本公司”“这一方案”指什么。Contextual Retrieval 在索引前给片段加简短文档背景，同时用于向量与字词检索；缓存可减少重复处理长全文的成本。背景也可能被生成错，因此保留原片段与出处。文章中基准测试的相对降幅，不保证会在你的资料上重现。

Qdrant 的多路预取与融合、Weaviate 的 BM25F/向量混合，是产品对这些概念的实现方式。参数名称和分数语义不同，迁移时要验证排序方向、归一化、权限过滤与缺失值。完整框架官网不是额外必读门槛。

## Memory 必修：存储模型与写入时机

LangGraph 的 checkpointer 保存一条 thread 的执行状态，store 可用于跨 thread 的数据。InMemoryStore 不会跨进程保留。用户 namespace 应由服务端确定；同一偏好在不同工作空间可以有不同版本与用途。

Hot path 在回应过程中更新记忆，及时但增加延迟；后台写入能减少等待，却要处理重复事件、晚到更新和冲突。明确来源和版本，避免昨天的后台任务把今天修改的偏好覆盖掉。

CoALA 把工作记忆、长期的语义/经历/程序性记忆及行动决策放入统一分析框架。它是分类与设计视角，不是安装一个库就能获得可靠记忆。Generative Agents 使用经验流、时间近度、重要性、相关性检索，再反思和计划；其角色可信度研究不能直接证明生产系统的隐私与事实可靠性。

Mem0、Letta、LangMem、Graphiti 等提供不同抽取、存储、检索或关系建模能力。先用表保存一项固定偏好，再按需要扩展；选库时实际测新增、查询、更新、删除、跨用户隔离、重启、过期。厂商自测结果不能替代自己的测试。

本地原课目录另含 advanced-rag 与 agent-memory 的完整小节、实验要求和所有项目用途。它们已纳入本课，不需要跳转外站完成学习。
