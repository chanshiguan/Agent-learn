从症状定位到实验

主线必读

找不到答案先查导入、切分和权限；资料在候选里但排太后，检查排序；证据已给到模型却回答错误，检查生成与引用；重启后偏好消失，检查存储。不要用“换更大模型”同时掩盖全部问题。

检索指标与答案指标分开。Hit@k 至少命中一个相关片段；Recall@k 衡量找回比例；MRR 看第一个相关结果靠前程度；nDCG 可以给强相关和弱相关不同权重。答案还要看相关性、证据支持与引用正确。资料本身可能过时，即使回答忠实引用，也不保证现实事实正确。

混合检索与 Reranker

主线必读

向量常帮助同义表达，字词检索常帮助专有名词、编号和精确短语。混合检索从两路取候选，再融合。不要直接相加一个系统的余弦相似度和另一个系统未经归一化的 BM25 分数。

RRF 使用各列表名次：某文段贡献为 1/(常数+名次)，跨列表相加，再排序。下面程序有完整融合与指标；综合助手中的 grounded_rag 也按这个思路融合查询结果。固定排名实验说明算法，语义效果要用实际 embedding 单独测。

"""离线排名实验：演示 RRF 与指标，不冒充真实 embedding 模型。"""

# 固定排名实验不调用语义模型；用小列表先核对融合和指标的计算。


# 同一 ID 在不同列表的倒数排名贡献相加；不要求各路原始分数同尺度。
def reciprocal_rank_fusion(rankings, k=60):
    scores = {}
    for ranking in rankings:
        if len(set(ranking)) != len(ranking):
            raise ValueError("单路排名不能有重复 ID")
        for rank, item in enumerate(ranking, 1):
            scores[item] = scores.get(item, 0) + 1 / (k + rank)
    return sorted(scores, key=lambda item: (-scores[item], item))


# 根据相关 ID 集合计算命中与召回；返回数量 k 不是召回率的分母。
def metrics(ranking, relevant, k):
    selected = ranking[:k]
    hits = set(selected) & set(relevant)
    first = next((i for i, item in enumerate(selected, 1) if item in relevant), None)
    return {"hit": int(bool(hits)), "recall": len(hits) / len(relevant) if relevant else 0,
            "reciprocal_rank": 1 / first if first else 0}


if __name__ == "__main__":
    dense = ["d2", "d1", "d3"]
    keyword = ["d1", "d3", "d2"]
    fused = reciprocal_rank_fusion([dense, keyword])
    for name, ranking in [("向量排名（固定输入）", dense), ("词法排名（固定输入）", keyword), ("RRF", fused)]:
        print(name, ranking, metrics(ranking, {"d1"}, 1))

Reranker 把问题与每个候选一起评分，再挑少量证据。它看不到没进入候选的文段，所以不能拯救召回失败。检索 k 大、生成用 k 小是常见分工，但阈值必须用自己的样本确定。

原进阶要求的 A/B/C 实验分别是纯向量、向量加 BM25、混合加重排。20 题完整实验与答案提供同一题集三组代码及实际参考结果。先保留 A，加入 B 时不同时改变切分；再加 C 时固定候选数。程序报告没改善也是有效结论，不能为了好看删失败题。

Query Transformation 与 Contextual Retrieval

主线必读

改写问题先补明确的同义表达或省略信息；Multi-query 从不同角度发出多个查询并去重；分解把复合问题拆成需要独立证据的小问。每多发一次查询都增加延迟与错误面，记录原问题和变换后问题，检查有没有偷偷改变意图。

HyDE 先生成假想答案，用它帮助找到类似资料；这份假想文本不是真证据，最终回答仍须用实际取回的来源。Contextual Retrieval 则在建索引时给片段加所属文档背景，缓解“该方案”离开全文后不明所指；同时保留原文，防止生成背景写错后污染索引。

本章的概念不是要求你复现论文训练。独立迁移题可先用受控同义词表做查询改写，清楚标记为规则基线；不能把它命名为完整 HyDE 或 Self-RAG。

GraphRAG、LightRAG 与摘要树

必读概念 · 实作按需

必读方法与适用条件；图检索和摘要树的具体产品实现选做。

问题要跨文档连接人物、事件和组织时，实体关系图可能有帮助。步骤是抽取实体和关系 → 合并同义实体 → 保留关系出处 → 根据问题检索子图或社区摘要 → 回到证据回答。实体合并错误会把不同人混为一人；摘要丢掉例外会放大错误。因此每条关系要能追到原片段，图只是索引。

GraphRAG 与 LightRAG 是不同实现，不应把名称互换。RAPTOR 按文本相似性聚类、为组生成摘要，再递归形成多层索引，适合跨层次问题；叶子证据仍要保留。普通手写目录不是完整摘要树算法。图和树的重建成本、删除传播与资料更新频率，是选型的一部分。

Corrective、Self 与 Adaptive RAG

必读概念 · 实作按需

必读何时修正、反思或切换流程；额外系统实现选做。

Corrective RAG 评估检索质量，在不足时触发补救；Self-RAG 使用专门训练的反思标记控制检索与生成；Adaptive RAG 按问题复杂度选择不检索、单步或多步策略。普通 if/else 可以教控制责任，却不能冒充这些训练方法的完整复现。

本地可操作的共同骨架：检索 → 检查候选能否支持问题 → 最多一次改写再检索 → 有证据回答／没证据拒答。评分器也是会犯错的组件，先准备人工标注的相关/无关样例；循环达到上限必须返回不足，而不是编造。DSPy 把程序模块、数据和指标作为优化对象；只有开发集参与优化，保留集不能逐题喂回。

长期记忆的设计选择

主线必读

短期工作状态围绕 thread 保存；长期状态围绕可信用户或工作空间保存。语义记忆回答“知道什么”，经历记忆回答“发生什么”，程序性记忆回答“怎么做”。CoALA 提供分类和行动循环的视角；Generative Agents 的经验检索、反思和计划用于模拟行为，不等于事实正确的个人助理。

写入方式也有区别：回应过程中保存偏好及时但增加耗时；后台提取减少等待，却可能晚到、重复或覆盖新信息。使用来源、版本与更新时间比较；过期信息先重新确认，不能因为语义相似就当最新。

最小选择顺序：先保存一项结构化偏好 → 加更新和删除 → 测用户隔离与重启 → 确有开放文本搜索需求再加向量记忆 → 只有时间关系复杂时才考虑图。Mem0、Letta、LangMem、Graphiti 等是不同实现工具，选择前用同一生命周期题集验证，不能用厂商示例“添加成功”代替全流程验收。

最终选型记录参考

主线必读

问题：退款例外被漏掉。证据：题五普通退款文段命中，例外片段未进前三。候选改动：只增加字词召回和融合。保持：资料、切分、模型、答案要求。观察：题五两个来源是否都进入，其他题是否回退，耗时变化。拒绝条件：出现其他用户资料；或关键事实错误。结论按实际输出填写，不预填“更好”。

这份记录才是进阶题的完整思考过程。你可以不用任何第三方图框架完成选择与对照；选修框架安装不是理解这些方法的前提。
