必修一 · Ollama Tool Calling

要点是把工具能力写入请求，让模型返回工具调用，再将执行结果放回历史。它支持单次往返，也支持多工具和多轮交互。

一次返回多个工具请求时，应处理整组请求并返回每个结果。对话进入下一轮，模型才能据观察决定继续调用或回答。流式模式需要先收齐工具参数，不能拿未完成的片段执行。

原生 Ollama 的工具参数通常是对象，结果消息可用 tool_name。兼容 Chat Completions 则按 function.arguments 和 tool_call_id 处理。本课的主线固定使用后者，不混用两套字段。

本地对应：单工具往返、多工具与循环。先跑成功路径，再用上限测试检查持续调用的情况。

必修二 · Anthropic How Tool Use Works

工具接口是一份契约：程序提供可用操作与输入说明，模型决定提出哪个请求，执行端运行操作，再将结果送回模型。模型不会自行运行你本机的函数实现。

client tool 在你的程序中执行。即使工具 Schema 来自厂商，例如某些桌面或编辑器工具，其执行位置也可能仍在客户端。server tool 则由供应商基础设施执行，不能机械套用本地函数的回传流程。

对 client tool，Claude 返回 tool_use 内容块和相应停止原因。程序读取 id、name、input，执行后发回 tool_result。模型可以继续提出工具请求，直到形成最终回答。

消息格式与异常处理见本页 S6 和单元 7 的完整实现。使用哪家模型不改变程序仍需负责输入验证、权限与执行边界这一点。

必修三 · ReAct 原始论文

论文由 Shunyu Yao 等人提出，将语言推理与环境行动交错：行动带来新的观察，观察帮助模型调整之后的决策。它在知识问答与交互任务中研究这种组合，而不是仅靠一次性生成答案或固定行动序列。

论文任务包括 HotpotQA、FEVER、ALFWorld 和 WebShop。它展示的是特定模型与实验设置下的效果，不意味着所有工具任务只要加 ReAct 就提高。错误的早期假设、检索失败和反复无效行动仍可能造成失败。

本课借鉴论文中的反馈循环，使用现代原生工具调用来演示，没有复现论文完整的提示轨迹或实验环境。学习时重点观察 action、observation 与后续参数之间是否有因果联系，不要求展示私有思维链。

本地练习：把查到的温度交给换算工具；检查第二次调用发生在结果之后。如果后一步只是提前猜值，最终答案正确也没证明完成了交互式推理。

S4 · Ollama 的 OpenAI 兼容接口

SDK 是客户端，模型由请求地址决定。本地 base_url 指向 localhost:11434/v1，api_key 占位值不代表云端授权。兼容接口覆盖部分 OpenAI API，不承诺每个字段或保证都一致。原生与兼容协议要分别核对。

S5 · 工具定义

工具名称要能对应一个具体动作；描述说清用途、适用条件和边界；每个参数说明类型、含义与合法选择。不要把用户没授权的业务动作混入一个模糊的万能工具。完整接口见单元 2。

S6 · Anthropic 请求与结果处理

tool_use 使用 id、name、input。结果放在 user 消息的 tool_result 块，用 tool_use_id 原样关联；失败加 is_error=true。结果消息紧接对应 assistant；多请求返回对应的整组结果。保留 assistant 完整内容块，展示答案时只提取 text。外部结果按不可信数据处理。

S7 · OpenAI Function Calling

本课使用 Chat Completions：tools 包含 type/function，名称和 parameters 在 function 内；返回 tool_calls，每条有独立 id，结果用 role=tool 和 tool_call_id。Responses API 的工具、输出项与结果结构不同，不能直接照搬这套消息格式。strict 是服务支持范围内的结构约束，不是业务授权。

S8 · 结构化输出

本地 Ollama 可对响应指定 JSON 或 Schema 格式。JSON 语法正确、字段结构合规、内容语义正确是三道不同检查。模型拒答、输出截断或抽取值错误时，不能因为拿到了一个对象就算成功。

S9 · JSON Schema

properties 声明属性，required 指定必填，additionalProperties 控制未声明属性。它们相互独立。enum 限制可选值，minimum/maximum 限制数值范围。应用权限、真实数据存在性与业务合法性仍由程序检查。

S10 · SDK 超时与重试

SDK 可能自带重试。为了控制尝试总数，要明确关闭或设置它，再决定是否自己重试。请求超时不证明服务端没有执行；写操作重试需要幂等设计。本课为只读工具，传输最多额外重试一次。

S11 · 顺序与并行工具

多个互不依赖的查询可以形成一批调用；后一步依赖前一步结果时，必须等待观察再继续。主线默认顺序执行，单元10提供真正并发执行的完整替代入口和重叠测试。

S12 · 严格工具约束

严格参数约束有助于让请求符合接口形状。它既不证明模型选对工具，也不证明当前登录用户有权执行该操作。不同服务的参数名与支持范围不同；本课用 Python 再验证，不从“兼容”推断严格保证。

S13 · Reflexion

Reflexion 根据任务反馈总结文字经验，再保存这些经验，供后续尝试参考；这个过程不会通过本次交互更新模型权重。单元 12 提供完整的最小实现和可选文件记忆，更完整的记忆架构留待后续阶段。

S14 · Self-Refine

Self-Refine 通过生成、反馈和修订反复改进当前输出。反馈者也可能出错，修订要用明确标准验收，并允许原答案已经正确。单元12提供完整代码、独立规则检查和拒绝退步的测试。

扩展主题的本地学习入口

流式、工具选择、并发、论文方法、反思、类型化生成和代码行动分别有独立单元。下面列出知识来源，点击本地链接即可进入相应讲解。

S15 · Instructor：类型验证与有限重试

Instructor 在模型客户端上增加 response_model 与验证失败后的重新尝试。Pydantic 定义可检查的数据契约；程序仍需决定哪些业务规则必须满足、允许几次尝试。完整教学在单元13。

S16 · Outlines：输出类型与生成约束

Outlines 用输出类型组织结构化生成。连接 Ollama 时，本例将 JSON Schema 交给后端，而非在 Python 客户端逐token控制远端模型。不同后端支持的 Schema、正则或文法范围不同。完整代码在单元13。

S17 · CodeAct：把代码作为行动

CodeAct 将可执行代码作为行动表示，便于表达变量、计算和多个工具的组合，并通过执行反馈继续处理。完整 Python 执行器需要独立隔离策略。本课用原创受限解释器展示关键流程，见单元14。

S18 · Python AST

ast.parse 将源码变成语法树，不会因为解析就运行代码。本课只解释明确列出的节点；解析成功本身不代表代码安全。未实现的语法统一拒绝。

S19 · Python线程池

submit 提交函数并返回 Future，result 取得对应结果。线程池可以重叠等待型工作；超时等待不等于停止已开始的线程。完整并发案例在单元10。

S20 · 代码执行隔离

本课解释器没有文件、网络、导入或任意宿主函数入口，只适合教学中的有限任务。要运行完整Python，应另外配置进程/容器或远程隔离、资源限制和凭证边界，不能靠删除builtins或一段提示词获得完整隔离。
