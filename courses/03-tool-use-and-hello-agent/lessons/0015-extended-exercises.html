2. 选择模式：别把指定工具当路由能力

扩展选读

分别运行auto、none、required、specific，记录首轮是否有tool_calls。解释specific成功为什么不能证明模型会自行选工具，以及后续为什么恢复auto。

参考答案

specific由程序明确指定工具；auto才保留模型的路由决定。持续强制每轮调用可能无法自然结束。none还需程序保持执行权限约束。完整代码为10_tool_choice.py。

3. 并发：用重叠证据验收

扩展选读

运行11_parallel_tools.py，比较实际输出时长。然后运行Barrier测试，解释两名工作线程必须同时到达Barrier才继续，为什么这比断言“耗时小于某个数字”更稳定。

# 运行指定测试；discover 会查找匹配的测试文件，-v 会逐项显示结果。

参考答案

两个任务并发执行时，都能到达 Barrier；如果顺序执行，第一个任务会一直等到超时。测试还会检查返回结果是否与原调用顺序对应，避免按完成顺序把 ID 配错。完整代码和测试都已提供。
