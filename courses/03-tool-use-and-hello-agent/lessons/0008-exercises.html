1. 先闭卷回忆，再运行程序

主线必读

这一页是课后练习。先不翻正文写出答案，再展开核对。代码练习直接修改本课副本，保留原始可运行版本作为对照。每题都有可观察的验收条件。

题 1：用自己的话写出五步往返

按 schema、call、execute、result、answer 解释每一步由谁负责。再说明为什么一次查天气通常要问模型两次。

参考答案与检查点

程序定义 Schema；模型提出工具请求；程序验证并执行函数；程序把对应 ID 的结果交回；模型根据结果回答。第一轮还没有结果，第二轮才看得到结果。完整消息历史必须包含 assistant 请求和 tool 结果。

题 2：只会写 JSON，算不算调用了工具

模型 content 打印出一个含 name 和 arguments 的 JSON，但 tool_calls 为空。它是否完成了本课原生工具调用？程序应该自动执行这段文字吗？

参考答案与检查点

没有。它生成了普通文字，没有按当前原生协议返回工具请求。不能把文字里看起来像函数的片段直接执行。记录原始响应，核对工具支持和请求格式。

题 3：检查一条消息序列

历史只有 user 问题和 tool 结果，遗漏 assistant 工具请求。指出缺失的角色、ID 的关联，以及修复位置。

参考答案与检查点

应先保存包含 tool_calls 的完整 assistant 消息，再为每个 call 添加同 ID 的 tool 结果；不能只把一个城市名或结果贴回历史。

题 5：用已有代码完成一个新计算

让 Agent 先计算 18+7，再将结果除以 5。不能在入口文件里硬编码答案。

# 运行有界工具循环。
python 03_agent_loop.py "先用工具计算 18 加 7，再把实际结果除以 5。"

验收：出现 add 与 divide，两次调用在不同模型轮次；第二次 left=25、right=5；最后答案为 5。若模型一次写出两个调用且提前猜参数，这一题不通过。

完整参考实现在哪里

原有 tools.py、agent.py、model_client.py 与 03_agent_loop.py 已支持此题，无需补充代码。完整代码集包含全部四个文件。先证明已有通用循环能完成新问题，再考虑加代码。

题 6：错误一定不会执行

运行离线测试，定位“额外字段”“除以零”“未知工具”对应测试。再找出校验发生在执行函数之前的那一行。

验收：三类输入均返回 ok=false；未授权工具不会执行；模型拿到的是错误结果而非伪造成功。完整测试是test_agent.py，可直接运行，无空函数需要补。

题 7：证明循环会停

运行 test_step_limit，阅读两轮持续请求的测试替身。说明为什么“模型不继续”与“程序强制停止”是两种独立停止条件。

# 运行指定测试；discover 会查找匹配的测试文件，-v 会逐项显示结果。
python -m unittest test_agent.LoopTests.test_step_limit -v

验收：持续请求在两轮后抛出上限错误；普通问候一轮即结束。不靠人工按 Ctrl+C 验收。

题 8：Schema 实验

先跑 good 的一轮五题，再跑 weak 与 good 各五轮。将结果按失败类型分类。之后只恢复弱版本的 description，再重新比较，验证描述是否真有帮助。

验收：记录真实任务数和成功数；保留答案及轨迹；不混改模型、题目和循环；不把离线脚本成绩写成模型成绩。完整评测代码和题目已经提供。
