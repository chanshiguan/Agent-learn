1. 这一阶段真正要交付什么

主线必读

第二课训练你把任务描述清楚。第三课开始，模型除了回答，还可以提出“请调用某个工具”的请求。你负责写程序，把请求检查清楚、执行函数，再把结果交回模型。

目标是做出一个天气与计算助手：能选择工具，能使用前一个工具结果，能在失败时说明原因，并且一定会在上限内停止。主线不引入 Agent 框架，先看清循环本身。

定义接口 → 模型请求 → 程序检查与执行 → 回传结果 → 模型回答或继续

2. 八个词，只按职责记

主线必读
术语白话解释本课对应物
Tool Use用外部能力补资料或完成动作查询固定天气数据、算术、换算
Function Calling模型按协议提出函数名称与参数名称为 get_weather，参数是 city
Tool Schema给模型看的接口说明名称、用途、字段、类型、必填项
Tool Call模型提出的一次请求带独立 ID 的工具工作单
Tool Result程序交回的成功数据或错误26°C，或“没有该城市数据”
Agent Loop模型和工具来回交互的有界循环本课 run_agent 函数
ReAct交替决定下一步、行动、读观察先查气温，再用实际气温换算
Structured Output把最终数据放进指定结构从现成句子抽取城市与温度 JSON

这一课先用“模型 + 工具 + 有界循环”来理解 Agent。不同研究和产品对 Agent 的定义可能更宽泛，学习时先看清程序做了什么，不必纠结名称。

5. 一次性准备环境

主线必读

沿用项目现有虚拟环境和已经安装的 gemma4:e4b。本课固定 SDK 版本，减少版本差异对案例的影响。已经在 ai-learn 目录时跳过第一条 cd；终端已激活 .venv 时跳过 source；依赖版本已符合 requirements.txt 时，不用重复安装。最后的测试用来检查程序是否正常，不会调用真实模型。

# 已经在项目根目录时，不用重复执行下一行。
cd /Users/owen/Documents/ai-learn
# 让本终端的 python 指向项目虚拟环境；已激活时可跳过。
source .venv/bin/activate
# 按 txt 中列出的包名和版本安装依赖，不是下载课程正文；环境已满足时可跳过。
python -m pip install -r courses/03-tool-use-and-hello-agent/examples/requirements.txt
# 查看本机已安装的模型，不会下载新模型。
ollama list
# 下面的测试和短命令从案例目录执行。
cd courses/03-tool-use-and-hello-agent/examples
# 发现并运行所有 test_*.py，-v 会显示各项结果；这里不请求模型。
python -m unittest discover -p 'test_*.py' -v

如果 Ollama 应用已经运行，不要重复启动服务。如果终端提示无法连接，先打开 Ollama 应用；也可以在另一个终端运行 ollama serve。只有模型列表里没有目标模型时，才执行 ollama pull gemma4:e4b；下载会占磁盘和带宽。

这里的 api_key="ollama" 是本地接口占位值。请求地址写死为 localhost，不会自动转到 OpenAI 云端。导入 OpenAI Python SDK，并不意味着在使用 OpenAI 模型。换模型可设置 OLLAMA_MODEL，但还要核对 reasoning_effort 参数兼容性。

6. 两类验证各证明什么

主线必读

离线测试：用固定响应代替模型，检查程序是否正确保存消息、返回错误、停止循环。真实模型运行：检查模型会不会正确选择工具、填参数、使用结果。离线测试通过后，还需要真实模型评测。

本地主线没有按 token 收取的云 API 费用，但会用本机内存、电力和运行时间。完整五轮 Schema 对比共 50 个任务，先跑单题和一轮小评测，再决定是否跑完。

7. 学习顺序

主线必读

先学单元 1–4，跑通模型与工具之间的往返；再学 5–7，处理错误并理解必修阅读，随后用单元 8 检查基础能力。单元 9–14 继续讲流式、并发、研究方法和扩展案例，单元 15 是最后的综合检查，可以分多次完成。
