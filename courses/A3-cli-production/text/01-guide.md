# A3：把 CLI Agent 接入团队流程

A1 让你完成一次操作，A2 让流程可以复用，第五课核心补上扩展机制。这里继续解决团队交付：别人能否装好、跑通、看懂结果并撤销配置。先读工作过程与 CI 配置，再按原题完成连接、审查、收据和安装验收，最后进入结业 A。

## 先修与安全阶梯

先完成 A1、A2、第五课核心。先本地只读，再受限工具连接，再只读 CI，最后才考虑需要批准的修改与发布。多人一起使用时，仍要核对结果是否正确，还需要把版本、安装、权限和回滚方法写清楚。

## CLI-9：只连接一个 MCP

先用第五课的只读 server 理解目录限制，再按 [CLI-9–12 完整样例](04-original-delivery.md)连接原题的官方 filesystem server，测试合法读取、越界拒绝和移除连接。官方包也含写入工具，目录受限并不等于只读。记录 server 来源、版本、命令、允许目录、配置 scope 和撤销方式。MCP 协议连接成功不代表服务器可信；任何被启动的程序仍有实际系统权限。

## CLI-10：只读 CI Review

先用同仓库测试 PR，限制 contents:read，不提供写入或部署凭证。输出保存在 artifact 或 job summary，由人查看。评审评论如果需要写权限，应单独明确；本课不替你向 GitHub 发布评论。

examples/review-workflow.yml 读取 PR 的实际差异，调用只读 Codex Action 并保存审查产物。完整配置、安装与验收在实作章，运行需要云端凭证和额度。不要用 pull_request_target 加高权限密钥去执行不可信 PR 的任意代码；即使只读 token，执行环境也要隔离。

下载到项目的 YAML 是模板，尚未安装到 .github/workflows，课程制作没有触发远端 CI。Actions 的主版本标签会变化，生产应按组织策略固定可信 commit 并维护更新。

## CLI-11：看运行收据

Provider、model、input/output tokens、耗时、结果和费用分开。查不到费用时写 null 或“未确认”；零表示已确认没有这项费用，含义不同；订阅和按量计费不能简单互换。examples/receipt.py 给出完整数据结构与基本检查，示范结果明确是 not_run。

收据需要关联任务与版本，才能追溯“哪个 Skill 在哪个模型上做了什么”。不要把聊天截屏当唯一记录；保留机器可读字段，避免记录凭证与无关原文。

## CLI-12：把 Skill 交给队友

在第二个干净 demo 中安装，写清文件路径、宿主版本、需要的工具、如何测试、如何卸载。测试不仅是能否找到命令，还包括缺文件、越界请求、输出不合格时是否停止。升级先测小样本，失败可恢复旧版本。

## 独立任务委派

委派给工作者前先规定目标、可访问范围、产物、证据和停止条件；不同任务尽量有独立文件归属。主流程负责整合与最终检查。Subagent 的摘要可能遗漏上下文，因此让它返回路径与可复查证据，而不是只有“没问题”。

## 完成标准

能向另一人说明安装、运行、权限、结果、失败和卸载；能从一份收据找到对应版本；没有批准就不会产生发布动作。完成 A3 即满足 A 线核心路线，Stage 8 是建议学习，不是结业 A 的强制门槛。
