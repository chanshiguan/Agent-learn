# 第七课课后练习

## 目标与交付

这一课要练习的是：怎样证明程序做对了，以及失败后怎样定位和恢复。请提交带版本的题集、逐题报告、一次 trace、批准/拒绝/恢复的收据、接口检查结果和失败分析。

## 四个核心练习

1. **Eval**：先运行原 02-eval 的版本化 5+3 题集，再完成综合项目控制题至少五题，包含普通成功、无资料、非法工具、预算耗尽、拒绝批准。说明 outcome 和 trajectory 各怎么判。改一项后列出回归。
2. **Observability**：为上述题保存任务 ID、每步类型、延迟、用量和错误。不保存原始密钥。用日志定位一次故意失败。
3. **批准与恢复**：用 06-safe-execution 创建待审任务；另起进程批准；重复恢复；用新任务测试拒绝；损坏状态副本必须停止。
4. **Deploy**：在本地运行 05-deploy，测试 /health、正常 /chat、坏请求和模型不可用。只在本机验证，不需要公开部署。

## 综合项目：有收据的研究助理

沿用三份获授权的小资料，保存来源标识与取得时间。生成摘要后暂停，用户可以修改、批准或拒绝。批准只对应确定版本，结果写入本地收据；中断后能继续，重复恢复不重复写入。用至少五个 development case 验收。

收据应包含任务、结果、来源、轨迹、耗时、用量、错误、状态版本与批准信息。输出“完成”但没有结果文件或记录，不通过。

## 排错与选修

模拟一种中断情况：ledger 已记下执行结果，state 却还停在 waiting。恢复时应补齐 completed 状态，不再重复执行。此示例不是并发事务实现；若要多个进程同时处理，提出数据库唯一键和事务方案，并测并发。

选修：运行辩论与 streaming 案例，用同样题集比较单 Agent 与多角色，实际读取缓存用量。两天后仅看一份失败 trace 重建过程；一周后升级一项配置并提交回归报告。


## 本课分层完成标准

1. 先回想：不看答案，用自己的话解释本课几个容易混淆的概念，再展开答案核对。
2. 跟着做：按[分步实作与完整参考](03-workshop.md)运行最小案例，保存输入和输出。
3. 自己做：换一份资料，或修改一个要求，完成自己的结果。只运行参考文件还不够。
4. 试着排错：故意触发一次失败，说明怎么找到原因、怎么修复，再运行正常例子确认恢复。

做完后，对照实作章末尾的评分标准逐项检查。分别记录代码是否运行成功、自动检查是否通过、内容是否经过人工核对，以及实际集成是否完成。待复核和未执行的项目暂不计为通过。卡住时，把课程编号、输入和实际输出发给我，一起定位问题。完成练习所需的步骤都在项目里。


## 独立回忆：先作答再展开

每题先用自己的话回答，再看参考答案。表述可以不同，但要说清谁负责、什么情况下成立。

<details><summary>参考答案与判断依据</summary>
