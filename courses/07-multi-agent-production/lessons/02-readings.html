Anthropic：Demystifying Evals

主线必读

Task 是测试题，trial 是一次试跑，transcript 是完整过程，outcome 是实际结果，grader 是判定方法。能力测试探索边界，回归测试保护已实现能力。先从真实失败收题，确保题目可解且参考可信，再扩展难度。

pass@k 关心多次尝试至少成功一次；pass^k 关心全部成功。若各次独立且成功概率恒定为 p，对应 1−(1−p)^k 与 p^k；实际评测不应随意假设独立。一次偶然成功不能说明稳定性。评测环境应隔离历史、共享缓存和残留文件，避免样本互相泄漏。

OpenAI Tracing

主线必读

Trace 表示一次工作，span 表示一个子操作；父子 ID 帮助还原调用关系。自动记录不免除脱敏责任。追加一个 processor 通常不会移除默认 exporter；若要彻底替换导出路径，需要相应替换配置。不要以为脱敏处理器报错会阻止另一导出器发送原文。

在本地实验中明确关闭 tracing 或选择受控处理器。日志访问范围、保留期和删除也属于设计。记录太多不仅费钱，还会使排错被噪声淹没。

OpenAI Human-in-the-loop

主线必读

需要批准的工具会产生 interruption；保存 RunState，展示具体动作，人批准或拒绝后再从原始顶层任务继续。聊天 Session 与执行 RunState 不是一回事。反序列化不等于认证，不应接受未经验证的客户端状态当成可信审批。

逐调用批准比对一个工具名永久放行更精确。不同角色如果复用 shell 这类广泛能力，需要分别检查范围。审批和工具执行之间仍需防内容变化与重复执行。

LangGraph Persistence 与 Interrupts

主线必读

Checkpointer 负责 thread 状态，Store 负责跨 thread 应用资料。InMemorySaver 不跨进程持久；持久后端应保存 schema 和版本，处理迁移与保留期限。

interrupt 在节点中产生暂停；用同一 thread_id 和 Command(resume=...) 恢复。恢复可能重跑节点开头，不是恢复 Python 指令指针。不要把不可重复操作放在中断前；也不要用宽泛异常捕获吞掉中断。多个中断的顺序应稳定，payload 应可序列化。

Building Effective Agents 与长期任务

主线必读

从简单可组合的形状开始，工具接口和环境反馈比无限增长的 Prompt 更重要。长期任务先建立特性清单、可重复启动方式、进度记录和版本控制；每次接手先验证现有状态，一次推进一个可验收目标，再留下清晰交班。

基础设施噪声会影响评分：同模型在不同资源、超时、并发限制下可能得到不同分数。把环境失败和模型判断失败分开，固定资源并多次试跑；小幅差距不自动等于稳定能力差。

参考项目如何对应

主线必读

编排项目解决谁先做、如何传状态；评测项目组织题集和 grader；观测项目记录链路；部署项目提供执行环境；多 Agent 项目增加角色。它们可以组合，但功能名称相近不代表数据格式、权限模型或托管责任相同。原课程完整目录已本地保留，每项按用途和边界阅读，不要求全部安装。
