官方 Quickstart、Memory、Skills

主线必读

安装、认证、选择项目目录和理解权限是四个不同步骤。使用订阅登录与使用 API key 可能对应不同计费路径，不能从已装 SDK 推断已拥有额度。开始工作前先确认所在目录和可访问文件；规则文件解释项目，但账户权限由执行层控制。

Memory 文档讨论指令来源、作用范围、导入和自动记忆；学习重点是让常用信息可找到并保持简短。Skills 文档讨论按需加载、参数、独立上下文和工具许可。给一个 Skill 写十条“不要”不如同时缩小工具集、给出结构化输出、明确失败状态，再用正反例测试。

官方 MCP、Hooks、Plugins

主线必读

MCP 注册一条连接；scope 决定配置属于本地项目、共享项目或用户。共享配置可能启动外部程序，因此需要检查命令和参数。服务器返回的内容属于资料，不是更高优先级的指令。撤销连接也不自动撤销已经泄露的凭证。

Hook 的输入是事件数据，输出与退出状态具有特定语义。先观察事件名，再学习阻断规则，避免一次配置错误导致所有工作无法继续。日志默认最少化；令牌、文件内容、访问记录不能随意交给第三方收集服务。

Plugin 把可重用组件作为版本一起发布；Marketplace 是版本与来源索引。升级前保留可恢复版本，测试安装和卸载，不把“安装成功”当“权限正确”。本课以本地配置练习为主，不要求发布市场。

主线必读

这些场景完整模板已随原仓库 subagent-cookbook 本地化。学习时不必背下 15 种身份。每次委派都要给足完成任务所需的信息，限定可用资料，并要求对方提供证据。复杂实现不适合只给一句“帮我做好”。

Subagent 进阶排错

主线必读

按顺序检查：配置有没有加载；description 是否能区分使用条件；允许工具是否足够又不过量；任务是否缺少主会话背景；模型、轮数与成本是否匹配。description 太宽会误触发，过长会让关键条件不突出。不要依靠大写 PROACTIVELY 当魔法开关。

Parallel 是独立任务并发；Pipeline 是前后依赖；Meta-agent 是继续委派的角色。它们需要不同的结束和合并规则。当前文档允许嵌套不代表每个任务都值得嵌套。原资料中“不能嵌套”等旧表述以这里的版本提醒为准。

Agent SDK、运行循环与托管

必读概念 · 实作按需

运行循环的停止与权限边界必读；SDK 接入和托管实作选做。

SDK 消息包含不同类型：模型文本、工具结果和终止结果。程序必须分别处理，尤其检查错误和预算终止。部署时还要考虑每个用户的工作目录、身份、会话存储、网络、资源上限、日志和清理；本机运行成功，只验证了当前环境；多个用户共用服务时，这些问题还要逐项处理。

完整原资料及所有项目清单在本课阅读入口中。上游客户端代码只说明接口包装，不能仅凭这些代码判断闭源运行时内部的全部实现。

Quickstart 的连续操作见安装与首次会话；Plugin、Dynamic workflows、SDK 的完整项目与答案见选修实作。
