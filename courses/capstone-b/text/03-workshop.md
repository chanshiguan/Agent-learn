## 为什么新版评分不只看关键词

“不是09:00开放”包含正确时间，却表达错误事实。引用一个真实 ID 也不代表它支持当前句子。本课评分器先查来源集合与实际检索轨迹；完全一致的可信摘录可自动判定；改写答案进入 NEEDS_REVIEW，人工核对后才算最终通过。没有检索轨迹、伪造工具结果、来源越界直接 FAIL。

## 每道示范题的人工答案标准

| 题目 | 必须正确表达 | 不能接受 |
|---|---|---|
| d1 周一时间 | 09:00–18:00，引用 hours | 否定这些时间、换日或编造例外 |
| d2 提前预约 | 至少提前1天，引用 booking | 把至少改成最多 |
| d3 退款 | 开课前至少24小时的条件，引用 cancel | 漏掉条件后说任何时候全额退 |
| d4 通话 | 门厅，引用 quiet | 把安静区当可通话区 |
| d5 教材 | 只能下载所报课程教材，引用 files | 扩成全部课程资料 |
| h1 周日 | 闭馆，引用 hours | 改为开放 |
| h2 最多提前 | 7天，引用 booking | 把至少与最多混淆 |
| h3 月球地址 | 资料不足，来源为空 | 猜地址或借不相关来源 |

除了答案，每题还查禁止动作和实际工具轨迹。所谓 holdout 在本教材是公开示范，读完这张表后不能再把它当你的盲测成绩。

## 提交自己的答案

`--submission` 接收 JSON，顶层是所选题集的题号，每项含 answer、source_ids、trace，trace 必须来自真实运行结果，不手填成功。可以把每题 run 的结果直接保存为这份对象。

```bash
# 运行 courses/capstone-b/examples/evaluate.py，按本行参数完成当前案例并核对输出。
.venv/bin/python courses/capstone-b/examples/evaluate.py
# 运行 courses/capstone-b/examples/evaluate.py，按本行参数完成当前案例并核对输出。
.venv/bin/python courses/capstone-b/examples/evaluate.py --submission /tmp/my-development.json
# 运行 courses/capstone-b/examples/evaluate.py，按本行参数完成当前案例并核对输出；--live 会进入真实服务路径，需先满足本章环境要求。
.venv/bin/python courses/capstone-b/examples/evaluate.py --live --trials 3
```

最后一条是15次真实任务，时间取决于本地模型。人工记录用“题号／trial／事实／引用／禁止动作／最终结论／理由”七列。有错写实际反例，不改答案后再冒充原输出。

## 完整失败分析参考

现象：一题答案引用了不存在 ID。层次：生成或引用契约，检索正常。复现：保留相同问题与工具输出，让假模型返回 fake ID。修复：在执行层检查引用属于本轮候选，拒绝后停止。回归：同题被拒、正常题继续通过、无证据题拒答。限制：合法 ID 仍可能不支持文本，所以继续人工语义评分。

迁移冲突题的答案应列两个互不兼容的来源，说明无法确定哪个有效，要求补版本或权威信息；不能按候选顺序选第一个。本示范关键词检索不自动解决任意同义词和冲突，它是你扩展评测的起点。

## 七维自评与完成门槛

问题定义看输入输出是否可验收；架构看组件职责与停止条件；正确性看逐条事实和工具行为；评测看五开发题、三个新保留题、多次试跑和评分校准；韧性看超时、无资料、非法工具与恢复；接口文档看干净环境复现；反思看一次有证据的改进。

每维分未达、基本、良好、优秀：缺产物为未达，单一正常路径为基本，有正反例且可重现为良好，有实际复用和受控比较为优秀。结业至少关键维度良好，无越权或伪造结果。最终交程序、架构说明、逐题报告、README、失败分析和200字反思，不能只交总分截图。
