# 第四课必修与参考知识整合

## Anthropic：Building Effective Agents

这篇文章的重要区分是：workflow 由代码安排路线，agent 自主选择步骤。不要先选一个复杂框架再寻找问题。先尝试一次模型调用加检索或示例，再按需要添加流程。成本包含延迟、调用数和不可预测性。

文章中的五类流程是：Prompt chaining 把任务拆成可验证的阶段；Routing 把输入分给合适处理器；Parallelization 对独立部分同时处理，或从不同角度评审；Orchestrator-workers 动态拆任务；Evaluator-optimizer 用明确反馈修改产物。每增加一个步骤，都要能查看它的输入和输出，并明确什么结果算通过；否则很难判断这一步有没有用。

自主 Agent 适合路线难以提前列举、工具结果会改变下一步的任务。环境反馈比模型自己说“完成了”可靠。工具接口要让模型易于正确使用：清楚的字段、少歧义的名称、实际可定位的错误。先用少量例子检查工具说明，再扩大任务。

## LangGraph：Workflows and Agents / Overview

图显式表示状态和边。固定流程更容易预测；动态 Agent 能选择工具，但需要停止条件。模型调用可以只是一个节点，普通 Python 函数、验证器和人工中断也都可以是节点。

持久化把运行按 thread 分组保存，帮助恢复、审阅和回放。持久化不是恰好一次执行的保证：写外部系统后程序崩溃，恢复时仍可能重跑动作。要把“状态已保存”和“外部动作已发生”分开判断。状态迁移时还要验证旧版本字段。

## OpenAI Agents SDK：Orchestration 与 Handoffs

代码编排能直接给出 if/else、并行和执行顺序；模型编排让模型选择专家。Manager-as-tools 适合中心角色负责整合；Handoff 适合接收角色接管后续交互。交接时要明确哪些历史、摘要和工具权限会传过去。Trace 可以显示调用链，但日志里仍要避免密钥与完整个人资料。

## CrewAI：Quickstart 与 Flow

Crew 组织角色和任务，Flow 管理事件、状态与控制路径。快速写出角色不等于做好失败恢复。把研究员的原始来源交给作者，比只给“研究员说值得买”的结论更可核查。框架版本变化会影响配置格式；本课保留原例依赖范围与实际源码，不把某个版本的配置当永久标准。

## 多 Agent 研究与反例

Anthropic 的研究系统说明：可拆开的广度搜索能从并行工作者受益，但耗费更多 token，且要严格控制任务边界和去重。Cognition 的文章提醒：共享细节被分散到不同上下文后，协作可能漏掉关键约束。两者并不矛盾，适用任务不同。论文里的相对提升、平均成本和特定基准，不能直接成为你的预计收益。

AutoGen、CAMEL、ChatDev 和 Generative Agents 分别展示可编程对话、多角色协作、软件流程和带记忆的模拟角色。阅读这些工作时抓住角色、消息协议、环境反馈和评测四点。社会角色设定或更多轮对话不能替代可信证据。AutoGen 的维护状态会变化；当前调查发现其官方仓库已有归档说明，不能把原课旧的维护状态视为永久事实。

## 工具目录该怎样读

Raw SDK 适合透明、简单的循环；LangGraph 强在显式状态与恢复；CrewAI 强在角色/任务组织；Pydantic AI 强在类型化输入输出和依赖；Smolagents 适合研究代码型行动。OpenAI Agents SDK、Microsoft Agent Framework、LlamaIndex、ADK 等是不同生态的候选，不是全部都要装。

Dynamic tool selection 先缩小候选工具集合，降低路由混乱；tool composition 把前一个输出接到后一个输入；tool-augmented retrieval 把检索器当工具。它们都需要可测试的数据接口。本地原课核对页保留完整项目清单和每项用途；案例实现了本课要求的四种框架；清单中的其他仓库供按需了解。
