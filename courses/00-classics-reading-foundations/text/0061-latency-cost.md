# 把一次模型调用拆成时间和用量

本单元预计 **30—45 分钟**。本章总用时见课程地图；首次安装、模型下载和等待他人审核另计。

## 两种数字不能互相代替

elapsed 是等待多久，token usage 是模型接口报告的输入/输出用量。线上费用还取决于实际服务的计费规则；本地模型没有同样的 API 账单，但仍消耗设备时间和内存。缺失 usage 就标未知，不能填 0 冒充免费。

选一次普通 RAG 和一次 Agent 请求，在 Network 响应里分别记录模型用量。Agent 的 usage 是多次调用列表，要累计每一轮，不能只看最后的答案。重排与查询改写也会增加额外调用。

做一张表：方法、资料 revision、输入字符数、模型调用次数、输入 token、输出 token、总耗时、费用依据。费率使用你实际服务当时的账单或正式报价，不在课程里写一个永久有效的价格。

## 做一个小而可解释的优化

保持问题不变，减少一块明显重复证据，再测一次。结果若更快，但关键依据也丢了，就不是可接受的优化。把支持度与成本放在同一行，避免只追求速度。

本章事件文件是本地可观测起点，不是完整监控平台。公司部署还要确定日志轮转、访问权限、留存、告警接收人和异常阈值。第 26 章测容量，第 29 章把这些归入上线证据。

**Agent 最后一轮只有 100 token，整次任务就是 100 吗？**

不是。还要累计之前的模型往返、查询改写或重排等调用。

**usage 缺失应该怎样记？**

标记未知，并说明无法据此计算准确费用；不能用 0 代替缺测。
