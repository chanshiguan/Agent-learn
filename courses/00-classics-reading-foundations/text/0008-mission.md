# 从五份讲稿开始做伴读助手

你最后要做的是一个能给学生和家长使用的名著伴读助手。它要能找到相关资料，说明回答依据，逐渐学会引导读者思考。眼下先把目标缩小：让电脑读懂你已有的五份讲稿，并让同一个程序在本机和 Docker 中运行。

本单元预计 **20—25 分钟**：理解目标约 8 分钟，写项目卡约 10 分钟，回顾约 5 分钟。整个导学预计 **55—75 分钟**。这些是学习时间估计，不是限时要求。

## 先看一个真实使用场景

学生正在读《狂人日记》，问：“开头为什么用文言文，后面又变成白话文？”家长可能接着问：“怎样提示孩子自己发现这两部分的区别？”

后来的助手需要先找出相关讲解，再组织回答。它还要分清哪些是作品原文，哪些是讲解者的理解。现在只靠模型直接回答，无法证明它读过你的讲稿。我们会先让资料处理过程清楚可见，再接检索和生成。

这一阶段会留下三样东西：五份输入讲稿、程序提取的 JSON、一次真实模型调用记录。这里的 JSON 是用文本保存结构化数据的格式，后面会亲手打开来看。

## 这几章怎样接起来

| 章节 | 预计完成时间 | 你会亲手做什么 |
|---|---|---|
| 导学 | 55—75 分钟 | 定目标、看资料、写首批问题 |
| 第 1 章 | 75—110 分钟 | 用 Python 读 Word，保存并核对 JSON |
| 第 2 章 | 65—95 分钟 | 用现成镜像运行同一程序，观察文件和日志 |
| 第 3 章 | 70—100 分钟 | 把依赖和程序做成自己的镜像 |
| 第 4 章 | 本地路线 75—115 分钟；线上路线 70—105 分钟 | 连接模型，保存响应，排查地址或配置错误 |

两条模型路线都做，第 4 章约 **95—145 分钟**。按本地路线完成全部内容，预计 **5 小时 40 分钟—8 小时 15 分钟**；首次安装和下载另留时间，网络慢时可能明显延长。建议分几次完成，每次只做一个短单元。

## 写一张项目卡

在练习目录创建 `project-card.md`。先按下面的内容填写，再用自己的话改两句。它不是商业计划书，只要能提醒你当前在解决什么问题。

```markdown
# 我的名著伴读项目

使用者：学生和家长。
第一本作品：《狂人日记》。
第一批资料：五份讲解稿，不将它们当作已核对的原著全文。
这一阶段的目标：读出资料，运行容器，接通一种真实模型。
成功证据：来源清单、提取结果、本机与容器对照、模型调用记录。
下一阶段：让模型根据提供的资料回答，并逐步加入检索。
```

练习目录是项目里的 `courses/00-classics-reading-foundations/examples/`。如果暂时不熟悉终端，就用 Finder 和文本编辑器创建文件。第一章会解释进入目录和运行脚本的方法。

<details class="answer-key"><summary>查看参考答案与通过标准</summary>

**这阶段做出什么？** 用 Python 读出五份讲稿中的样本，将结果保存为带来源的 JSON；把读取程序放进容器；接通一种真实模型并留下调用记录。

**怎样区分“模型有回答”和“回答用了资料”？** 前者只说明模型请求成功。后者还要检查程序找回了哪些资料、这些资料是否进入请求、答案能否由资料支持。本阶段尚未实现后一项。

**通过证据：**项目卡写明学生和家长是产品读者、输入是讲解稿，并列出这阶段与下一阶段的不同目标。表述不必逐字一致。
