## RAG 现在只多一条连接

顺序是：问题 → 当前作品可见片段 → 词面排序 → 上下文预算 → 模型解释 → 引用检查。生成模型没有被训练，知识库更新后换的是本次送入的证据。

第一条结果保存为 `data/live/ask.json`。运行第二条前另存第一条。逐条核对 `citations` 和 `sources`：合法编号只是起点，还要检查对应片段是否真的支持回答。允许文学解读有差异，但不允许凭空添加证据。

## 亲手拆开一条回答

用不同颜色标出：直接复述讲稿的句子、模型组织的解释、超出资料的内容。若一句话声称“鲁迅原文说”，回查它是否真的出现在已提供资料里；讲稿讲述者的说法不能自动升级为原著引文。

下一次把同一个问题用 `--book "三国演义"` 运行。没有可见证据时，程序直接返回不足，不调用生成模型。这比“让模型随便答，再提醒可能不准”更容易验证。

## 结果不稳定时

格式错误要留下失败记录，不能用手工改 JSON 冒充模型成功。证据有、答案偏，排查 Prompt 和模型；证据没有，排查检索。第 8 章把今天这套人工检查做成固定题集，之后每次优化都沿用。
