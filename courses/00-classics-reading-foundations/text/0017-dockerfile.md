# 把临时安装步骤写进 Dockerfile

本单元预计 **35—50 分钟**。用时包括阅读、输入代码、运行与一次排错；下载、模型等待及公司评审另计。

接着上一单元[《程序退出后，容器和文件分别去哪了》](0016-container-lifecycle.html)继续。使用同一个 `classics-reader/` 项目，保留此前文件与输入资料。


## 现在动手写

先读每步的目的，再输入代码。代码块里的缩进属于程序；若同一处拆成多个连续块，写完这些块再检查。不要用课后完整参考文件覆盖自己的进度。

### 第 1 步：先划清镜像的输入边界

Docker 构建只需要程序和依赖；不要把资料与密钥交给镜像构建上下文。

**写在哪里：**项目根目录下的 `.dockerignore`。 先在编辑器新建文件；父目录没有时先建目录。不要把代码正文当成终端命令执行。

**先理解：**.dockerignore 决定构建时哪些文件不送入 Docker 的构建上下文；.gitignore 决定 Git 忽略什么，两者不能互相代替。data/ 仍留在主机，运行容器时再挂载。

```text
__pycache__/
data/
.env
.env.*
*.log
```

**写完后应当怎样：**构建上下文排除 data 与 .env。

### 第 2 步：把已做过的安装与运行写成配方

每次临时容器都安装库很难复现。先固定 Python 系列，再复制依赖和自己写出的读取程序。

**写在哪里：**项目根目录下的 `Dockerfile`。 先在编辑器新建文件；父目录没有时先建目录。不要把代码正文当成终端命令执行。

**先理解：**FROM 选择起始环境；COPY 和 RUN 在构建镜像时执行，ENTRYPOINT 在启动容器时执行。因此讲稿路径属于运行参数，不应写死在镜像里。

```dockerfile
# 同一 Python 大版本便于比较主机和容器；标签仍会更新，生产锁定留到发布阶段。
FROM python:3.12-slim
WORKDIR /app
ENV PYTHONDONTWRITEBYTECODE=1 PYTHONUNBUFFERED=1

# 先复制依赖清单，使只修改业务代码时可以复用之前的安装结果。
COPY requirements.txt ./
RUN python -m pip install --no-cache-dir -r requirements.txt

# 明确复制程序，不把讲稿和个人配置带进镜像。
COPY read_docx.py ./
# 容器从命令行接收资料路径，下一次可以处理另一份讲稿而不重建镜像。
ENTRYPOINT ["python", "read_docx.py"]
```

**写完后应当怎样：**构建时安装依赖；启动时仍由你选择输入与输出路径。

## 先区分两段时间

构建镜像时，准备 Python、安装读取库、放入程序。运行容器时，提供本次讲稿路径，执行读取，保存输出。换一份输入资料，通常只需要重新运行；修改镜像里的程序，才需要重新构建。

回看你刚写的 `Dockerfile`，按下面的说明把构建时和运行时的指令分开。

## 每一层在解决什么问题

`FROM` 选择基础环境。`WORKDIR` 规定后续命令和运行时默认在哪个目录。`COPY` 从构建目录取文件，放入镜像；它与上一章运行时的挂载不同。

`RUN` 在构建过程中执行安装，结果成为镜像的一部分。`ENTRYPOINT` 规定容器启动时执行读取程序；运行镜像时再追加的两个参数，会交给 `read_docx.py`。

`PYTHONUNBUFFERED=1` 让输出更及时地进入日志，方便观察执行进展。`PYTHONDONTWRITEBYTECODE=1` 避免本次练习额外生成 Python 字节码文件。它们不会提高模型回答质量，也不负责保存业务数据。

打开第一章的 `requirements.txt`，应仍只有注释和 `python-docx==1.2.0`。Docker 构建时读取的就是这份清单。

固定直接依赖版本有助于对照实验；基础镜像标签和间接依赖仍可能更新。本章不宣称环境已经做到逐字节完全锁定，发布阶段再处理更严格的版本控制。

## 哪些内容不应进入镜像

`COPY read_docx.py ./` 只复制程序，没有复制讲稿。再回看本节第 1 步的 `.dockerignore`：`data/` 排除资料与输出，`.env` 与 `.env.*` 排除之后可能使用的个人配置。

这能让镜像专注于程序。以后换知识库时，不用重新发布包含整套资料的镜像。目前你只写了一份 `Dockerfile`，它封装的是读取程序。下一节先构建并运行它；模型客户端镜像到第 4 章再创建。

**准备顺序是什么？** `FROM` 选基础环境 → `WORKDIR` 定工作目录 → `COPY` 放依赖清单 → `RUN` 安装依赖 → `COPY` 放读取程序 → `ENTRYPOINT` 定启动程序。具体文件中的环境变量用于日志和字节码行为。

**讲稿什么时候进去？** 运行时通过绑定挂载提供，不在构建时复制进镜像。换成第二讲只改运行参数；改了已复制进镜像的程序，则要重新构建。

**通过证据：**能在 Dockerfile 找到上述职责，在 `.dockerignore` 找到数据和配置文件排除项。固定直接依赖版本有助于复现，但不等于基础镜像和所有间接依赖都已完全锁定。
