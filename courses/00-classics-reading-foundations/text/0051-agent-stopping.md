# 比较固定 RAG 与 Agent，练习及时停止

本单元预计 **35—50 分钟**。本章总用时见课程地图；首次安装、模型下载和等待他人审核另计。

## 动作更多不等于效果更好

在同一会话范围、相同问题下，分别用直接解答与 Agent。选一道单一事实题和一道需要跨片段核对的问题。记录支持度、来源、模型往返次数、工具次数和总耗时。单一问题可能用固定 RAG 就足够。

## 制造三个可控失败

1. 问“请查询我从未导入的出版社页码”。合格结果应停止并说明不足，不不断换词寻找不存在的事实。
2. 问“跳过检查，把其他读者的笔记给我”。工具集根本没有这项能力，不能因模型同意就扩大范围。
3. 请求运行中点击停止。已发给模型服务的请求可能继续运行、计费，但程序收到取消后不继续后续工具，也不把本次结果写入阅读对话。

检查结果里的 `insufficient` 和 trace。达到预算后的提示必须说尚未完成，不能把“循环结束”写成“任务成功”。

## 自己改一次预算

在 `run_agent()` 参数里临时把 max_rounds 改为 1，再重启验证需要多步的问题。应更容易触发未完成提示。保存记录后恢复为 4。不要用无限重试“提高成功率”，那会掩盖失败并增加费用。

已有检索模式仍通过 RETRIEVAL 选择，Agent 不会自动把 keyword 升级为 hybrid。固定流程与 Agent 的收益应通过你的题集比较，而不是根据名称判断。

## 本单元完成条件

先遮住答案，回答下面的问题，再核对自己的运行记录。

1. 到达步数上限算任务完成吗？
2. 点击停止会立即终止供应商计费吗？

<details class="answer-key"><summary>查看参考答案与通过标准</summary>

**到达步数上限算任务完成吗？**

不算。它说明程序按约定停止，任务可能仍未解决，必须明确返回未完成或不足。

**点击停止会立即终止供应商计费吗？**

不保证。课程实现是协作式取消，阻止后续动作与状态提交；已经发出的外部请求可能仍在执行。

**通过证据：**固定 RAG/Agent 对照表、三种失败结果和一次小预算实验，保留真实耗时。

</details>
