选读知识 / RAG 方法详解

Agentic RAG：让程序决定何时再查

预计 8—10 分钟不计入主线验收无需额外安装

固定流程通常每次先检索再回答。Agentic RAG 把检索作为工具，让模型参与决定何时查询、怎样查询、是否还需要更多资料。它改变的是流程控制，不只是换一个更大的生成模型。LangChain 的 Agentic RAG 说明

用伴读问题走一遍

读者要求比较第二讲与第四讲。一个可能的流程是：查第二讲 → 查第四讲 → 检查两边证据是否齐全 → 必要时补查 → 给出带来源的比较。这里是设计示例，不是已经实现的自动行为。

不过，这样明确的两讲比较也能用固定程序分别检索后合并完成。只有需要根据结果灵活选择下一步时，再考虑让 Agent 决策。动态路径会增加排错和评测难度。

灵活之后要补哪些边界

本项目后续应限定可调用的工具、资料范围、最大检索轮数和总耗时；证据不足时能结束并说明不足。还要记录每次查询和结果，否则读者只看到一句答案，开发者也很难知道为何查错。

讲稿文字是待分析的数据，不能因为其中出现“忽略之前要求”就当成系统指令。是否继续查资料，也不应由某段未经信任的文本直接决定。

与启发式伴读是什么关系

“先追问学生想法”是一种产品教学行为，可以先用明确流程实现，不必等复杂 Agent。后续 Agent 主要帮助选择工具、补充证据和管理任务；会调用工具，不等于就会教得好。

推荐选读

LangChain：检索架构比较（英文，约 10 分钟）。先比较固定流程与 Agentic RAG 的控制方式，代码无需照做。对于本课程，先保留可解释的固定问答基线，再评估动态决策是否真的改善任务完成。
