本地与线上模型，哪些相同，哪些不同

预计 10—12 分钟不计入主线验收无需额外安装

两条路线可以复用资料处理和大部分业务代码，但不能简单理解为“只改模型名，任何服务都能替换”。我们先约定一种兼容接口，再把差异收在配置和模型调用部分。

一次请求经过哪些角色

你的 Python 程序 → SDK 整理请求 → 模型服务接收请求 → 模型生成 → SDK 解析响应 → 程序保存记录。

SDK 是调用工具，不是模型本体。Ollama 是运行服务，模型权重是它需要加载的数据。线上路线则由供应商负责模型服务的运行。

比较项 本地路线 线上路线
算力来源 自己的学习设备 供应商服务
配置 本机地址、已下载模型名 HTTPS 地址、开通模型名、密钥
常见限制 内存、加载时间、本机并发 网络、额度、限流、接口权限
应当共用的部分 资料清洗、来源记录、问题集和业务规则 同左，但仍要重新评测输出行为
不能默认相同的部分 上下文长度、参数支持、工具调用、输出质量 要逐项核对，不能由“兼容”二字推断

Ollama 的兼容说明明确描述了支持范围，并区分本地服务的用法。接口形状兼容，不表示所有能力完全相同。Ollama 官方兼容说明

生成模型、Embedding、token 别混在一起

生成模型负责组织回答；Embedding 模型把文本转成可用于比较的数值表示，常用于找相近内容。接通聊天接口，并不代表已经能把讲稿向量化。后续若更换 Embedding 模型，通常还要重建对应向量索引，不能把不同表示空间的数据随意混用。

token 是模型处理文本时使用的单位，不能固定换算成一个汉字。上下文窗口约束一次请求可处理的内容；输出上限只限制生成部分。本课的 256 输出 token 不是允许塞入任意长度讲稿的承诺。

这些概念将服务于一个具体判断：回答不好，究竟是没找到资料、资料没放进请求，还是模型没有遵守要求？先保留请求与响应形状，再判断是哪一环。
