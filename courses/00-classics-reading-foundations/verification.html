后半另有 8 个阶段的浏览器交互检查，模型接口使用明确夹具，覆盖创建会话、进度、草稿修改批准、登录和家长进度。修复了本机测量客户端继承 SOCKS 代理导致启动失败的问题。本次从编辑记录重建的项目已真实调用本地 gemma4:e4b：有据问答、缺少页码时标记资料不足、Agent 调用 search_lectures、生成草稿后以测试确认请求写入一条笔记均完成。见本次真实调用记录。这几题仍不能代表稳定的文学质量。容器结果以本轮发布工作流日志为准；以下旧实验保留原有范围。

能证明什么

主要路径已在隔离环境跑通：读取 Word → 整理资料 → 检索 → 真实模型问答 → 工具调用 → HTTP 服务 → 生成草稿 → 人工确认保存。真实 Embedding 的编码、持久索引、缓存复用和跨进程查询也已执行。

这证明配套项目具备可运行的主要链路；它不等于所有模型、每台电脑、全部阅读问题都已通过验收。公司上线仍需要实际身份系统、业务题库和目标部署环境的验收。

真实模型实验

前一版完整工程验证使用已有的本地 gemma4:e4b，输出预算 1800 token，未指定推理强度。在编写设备的隔离副本中实际运行，不是对 M1 16 GB 或课程示例 Qwen 模型的性能背书。线上路线只检查配置、请求结构和错误处理，没有调用收费模型。

实测第一题能够引用第一讲解释两种叙述声音；Agent 真实调用 search_lectures 后给出引用；实际启动的 Uvicorn 接口完成第五讲问答、草稿生成、确认保存，笔记数为 1，就绪接口返回 200。可查看原始结果与观察。

同时保留失败：默认 900 token 预算曾截断答案；一次指定关闭推理的实验出现 Agent JSON 结构失败；初次页码回答虽承认资料缺失，却把 insufficient 标成 false；普通模型调用也没有遵守“两句话”的长度要求。这些不能算回答质量通过。程序已明确报告截断，提示词补清证据不足的含义，讲义增加预算及字段核对练习。修订后的两题复测见字段复测，少量复测不能替代稳定性评测。

真实向量实验

编码器为 sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2，固定提交 e8f8c211226b894fcb81acc59f3b34ba3efd5f42，CPU 执行。106 个块生成 384 维向量，保存到 Qdrant SDK 本地持久存储；重复建索引新增编码数为 0，另一进程成功查询。

首次实测发现新版库没有提供代码原先依赖的私有版本字段，导致索引失败。现在按公开 API 显式加载固定提交，并将同一版本写入索引契约。此记录不将 SDK 本地模式冒充 Docker 中的 Qdrant 服务。

自动检查与容器发布门槛

41 个 Python 测试和 4 个页面异步回归覆盖来源校验、范围过滤、身份隔离、旧版本冲突、取消、确认幂等、跨进程删除及迟到响应。浏览器还检查草稿编辑确认、输出作为文本显示、失败后清除旧答案、读者切换和响应式布局。测试替身只用于验证程序行为。

发布工作流在 Linux Runner 上重新运行测试，实际构建读取镜像和完整应用镜像，再启动 Compose，检查挂载、登录、RAG接口与Qdrant服务；随后实际构建修改标题的第二镜像，切换并撤回，核对页面显示。容器里的生成模型是明确标注的协议夹具；真实生成实验是上面单独记录的本地模型。Docker 现场日志见发布工作流，只有验证任务成功才会部署 Pages。

公开范围与剩余验收

公开 Git 分支独立于私人工作区的历史，只包含课程文件和新编五讲。DOCX 必须与公开 Markdown 的生成结果逐字节一致；网站按白名单发布，排除私人原稿、个人学习记录、密钥、模型缓存、数据库和运行输出。
