先整理一条消息，分清已知事实和待确认信息；再了解不同工具能做什么，最后完成自己的提醒草稿。这个分支可以直接学，不要求先走完整 A 线或 B 线。

不需要先学完整主线

身份分支选读

从整理一条虚构消息开始，完成后再决定是否需要 Agent。普通聊天适合解释和草稿；有资料问答先提供资料；要操作网页或其他应用才需要工具权限。个人 Agent 不是“可以接管一切”的同义词。

Goal 是目标，Context 是必要背景，Constraint 是限制，Draft 是草稿，Source 是事实出处，Permission 是权限，Approval 是具体动作批准，Receipt 是执行记录，Automation 是重复流程。最重要的是把草稿和已经发生的动作分开。

原练习：消息变成提醒草稿

身份分支选读

输入是一条虚构的消息，内容是通知提交海报。输出三块：Draft 写提醒文字；FactsCopied 列实际提取的事实；NeedsConfirmation 列缺失信息。只写“周五”却没有日期背景时，不换算成年月日；活动名、地点、渠道没写就问，不编造。

不发送、不创建真实提醒，是本练习的任务边界。如果模型说“已提醒”，却没有工具执行记录，就不能确认提醒真的创建了。即使以后接日历，也先展示标题、日期、时区、对象，再由用户批准。

四扇门按任务选

身份分支选读

日常问答与草稿：先用聊天。资料阅读与整理：提供自己有权使用的文件，要求来源。网页或电脑操作：使用受限浏览器/电脑工具并检查动作。重复跨应用事务：选择可观察、可撤销的自动化流程。不要为了简单改写一句话引入多个 Agent。

个人 Agent 的边界卡

身份分支选读

写清目的、资料、能做的动作、不能做的动作、什么情况必须停下、怎样验收。比如“整理这三条虚构消息，只输出草稿；缺日期则列待确认；不联系任何人”。这比“做我的全能助理”更容易判断成功。

记忆不是默认越多越好。只保留未来有用且你同意的信息，能够查看、更正和删除。敏感资料、账户凭证和别人的个人信息不应成为随手练习材料。

费用、权限与产品选择

身份分支选读

聊天订阅、API 调用、托管执行与本地模型有不同成本和权限。安装一个应用不代表已经授权它发送消息、管理银行账户或读取所有文件。产品名称相近也可能属于模型、运行工具、云服务和开源客户端等不同类别。

原课列了多种个人 Agent 项目。先看是否能只读试用、说明数据去向、提供停止与撤销、限制动作、显示真实收据；不要把宣传里的“自主”理解成可跳过检查。
