# 不猜日期、不混淆草稿和实际动作

## 单元一：原题消息与完整提醒

原消息说“小安星期五前把海报草稿交给小美，活动日期9月12日，未写交付时间”。reference-work 的 original_message 保留原题，Draft、FactsCopied、NeedsConfirmation 分别是可读提醒、抄出的事实与待确认项。小雨海报案例用于换场景练习，不能代替小安这道原题。

星期五不等于活动当天，9月12日没有给年份，消息也没有给具体几点。提醒可以原样保留这些信息，不能为了看起来完整猜出具体日期。谁交给谁也要照原句，不把收件人写成执行人。

## 单元二：写请求的五个部分

说明要做什么、只用哪些材料、输出格式、不能猜什么、如何核对。比如“只据这段消息，分三块输出，未知时间标待确认，保持草稿，不发送”。复杂任务先拆一步，发现错误时指出哪句与来源不符，再让模型局部修改，比重复“仔细一点”更有效。

不要把模型流畅表达当已查证。日期、金额、地址、联系人和是否已执行特别需要核对。遇到消息互相矛盾，列出两种说法和来源，停止生成确定提醒。模型声称“已经帮你提醒”却没有真实动作收据，不能当完成。

## 单元三：四种入口怎样选择

聊天适合草拟；连接器帮助搜索已授权账户资料；CLI 可读写限定目录并执行命令；本地 runtime 负责运行模型。它们不是高低等级。只想整理这段消息，不必装 CLI。重复整理本地文件才考虑 A 线，操作网页才考虑第八课。

连接前明确读什么、数据送去哪、能改什么、怎样撤销。Claude 的桌面与网页连接能力、ChatGPT Apps、Gemini 连接服务可能有不同权限和可用条件，不能把一个服务的授权当成所有工具授权。停用账户连接与删除已有数据副本是两件事。

Ollama 或 LM Studio 使用本地权重时可本地推理，但云模型、网页搜索、第三方工具和日志仍可能联网。判断是否不外发要看整条链，不能只看软件名字里有 local。账号条款与设置会变化，课程教你检查这些责任，不让你背某个永久开关位置。

## 单元四：个人 Agent 与持续任务

持续助手需明确目标、范围、何时停止、多久检查、怎样通知和撤销。让它记住偏好之前说明保存什么，之后应能查看、改正、删除。草稿到发送需要具体对象与内容确认；允许读消息不等于允许转发。没有确认渠道与收件人时，最有用的产物是待确认清单。
