# 从论文问题到可核对证据表

## 单元一：原练习的三个问题

原题问：论文解决什么问题、方法包含哪些部分、哪些实验支持结果以及限制。架构、实验任务和“是否证明所有任务最优”的判断用于补充核对，不能替代这三个问题。下面 reference-work 的 original_three_questions 已逐题回答，并标出位置、中文证据转述与支持范围。

本地资料对应 Attention Is All You Need v7 的 Introduction、Model Architecture 与 Results。主要问题是循环依赖限制并行；方法以注意力组织编码解码，并保留位置与前馈等结构；实验包括翻译、变体和句法分析。论文结论不意味着所有任务最优。原文极短摘录与中文解释分开，中文转述不伪装原文直引。完整论文没有被重新授权为本仓库 MIT。

## 单元二：引用的三步核对

第一步列断言，一句话包含两个事实就拆开。第二步找到能支持它的段落位置；标题相关但内容不支持，不能算引用。第三步核对范围：作者报告的结果、作者的解释、你自己的推断分别标注。

例如“翻译任务有效”不能扩成“所有任务有效”。两个论文用不同任务、数据切分或指标时，不直接比较数字。没有找到作者的明确限制段落，应写你的证据范围判断，不能编造“作者承认……”的引语。

## 单元四：文献工具的操作知识

带引用的 Notebook 流程是导入获授权来源 → 按问题检索 → 打开引用 → 同时读上下文 → 把支持或不支持写回笔记。引用只是入口，点击后没有支持仍要退回。上传前确认资料许可和工具数据处理范围；公开可读不自动授权转交任何服务。

Zotero 中条目存作者、年份、题名、出版信息，附件存 PDF，笔记存你的阅读判断。先核对元数据，再用 collection 按项目组织、tag 标阅读状态，重复条目先合并，最后生成引用与书目。同步条目与同步附件不是同一件事；引用格式正确不等于内容正确。

可重复研究要版本化代码、数据、参数与结果。DVC 用小元数据文件在 Git 中记录大文件版本，大文件另进 cache/remote；`dvc add` 不等于把数据上传远端。恢复版本要匹配代码与数据，管线明确依赖、命令和输出。MLflow 等记录参数、指标与产物，不能替你判断科学结论。Zenodo 发布要补标题、作者、版本、许可和数据说明；上传之后才有可追溯发布记录，课堂不要求实际公开。

PaperQA 等将检索和证据摘要接到答案；ASReview 帮助筛选候选文献，纳排理由仍需记录；repo2docker 从环境声明重建运行环境，不保证数据可访问或结果复现。自动研究 Agent 尤其应保留失败实验，不能只汇报最好的随机种子。

## 课末作业、提交与评分

复制 reference-work 的字段结构，先清空答案，自己完成原三问与一条“不受支持”的反例，再核对参考。提交文件例如 `/tmp/research-work.json`：

```bash
# 运行 courses/branch-researcher/examples/check_work.py，按本行参数完成当前案例并核对输出。
.venv/bin/python courses/branch-researcher/examples/check_work.py /tmp/research-work.json
```

结构缺失 FAIL；结构齐全 NEEDS_REVIEW。人工逐项要求：三问均回答、每条断言有定位、没有夸大实验、推断与作者话分开、未运行实验不写成功。这五项全部满足才通过。两天后不看表复述方法与限制；一周后换一篇获授权资料重做，不要求使用某个付费产品。
