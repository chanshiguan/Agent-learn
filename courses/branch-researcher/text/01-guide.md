# 研究人员分支：从摘要走到可核查的研究记录

本分支按“读懂问题 → 核对论文证据 → 完成证据表 → 记录可复现实验”学习。先用本地材料完成三问，不必先写 Agent；代码实验使用给定数据，之后再换自己的研究问题。

## 本分支的成果

形成“问题 → 来源 → 断言 → 证据 → 不确定性 → 实验”的记录。Agent 可以找候选论文、整理段落、生成代码草稿，但不能替你确认引用存在、研究结论适用或实验已成功。先做一篇论文的核对，再跨论文综合。

## 八个核心概念

Research question 是具体问题；Literature search 找候选；Citation 指向来源；Claim 是可核对断言；Evidence 是支持或反驳材料；Synthesis 比较多来源；Reproducibility 要求别人能按条件重复；Provenance 记录资料与结果从哪里来。引用很多不代表证据强，摘要相似也不代表方法相同。

## 原练习：Attention Is All You Need 的三个问题

原题有三个问题：论文解决什么问题，方法包含哪些部分，哪些实验支持结果以及结论有哪些限制。每条答案记录论文版本、章节或表格、原句或准确释义、是否支持以及限制。架构、实验任务和“是否证明所有任务最优”另作补充检查。不要只让模型回答“这篇论文讲什么”，那很难发现具体错误。

本地 input.json 使用明确标记的论文段落教学概述，让你先练断言核对；原论文结论是 Transformer 及其特定实验，不是“在所有任务上永远最佳”。正式写论文或复现实验时，需要针对原论文精确版本做逐表核对；本练习提供了理解任务所需的概念；其中的教学概述不是原始实验数据。

## 文献 inbox

把题名、作者、年份、稳定标识、来源、研究问题、方法、数据、主要结果、限制分开保存。搜索工具找到的是候选线索；出版年份、撤稿、更正和版本都要检查。相同论文不同平台链接不应计为两份独立证据。

先确定哪些论文纳入、哪些排除，再搜索，避免只收藏支持自己观点的文章。每次记录查询式、时间和筛选理由。无法获取全文时明确标记，只基于摘要回答摘要能支持的问题。

## 跨论文 synthesis

比较同一维度：数据集、任务、模型、baseline、指标、训练和推理预算、限制。结果不能直接比较时，说明原因，不把不同任务的分数放在一起判断谁更好。

模型生成的“共识”需要回到逐条来源。把每个综合判断拆成可核对 claim；证据相反时保留分歧，不通过措辞把它们强行合并。检索得不到反例不等于没有反例。

## 代码与实验

记录代码版本、依赖、数据版本、随机种子、硬件、配置、命令和输出。先复现小样本与 baseline，再改变一个变量。生成代码能运行只证明语法和部分逻辑，不证明论文方法已复现。

DVC 关注数据和管线版本，MLflow/W&B 等记录实验配置和结果；Git 记录代码，三类记录不能互相完全替代。训练集、验证集、测试集应分离，不能反复根据测试结果选参数后仍叫盲测。

## 投稿前检查

逐条核对事实引用、图表数据来源、实验是否真的执行、限制是否完整、作者责任和机构政策。不要用虚构 DOI 补齐参考文献。AI 生成的“评审意见”是检查线索，不能当独立学术同行评审。对研究诚信与期刊规定只采用实际适用的官方政策，不猜。
