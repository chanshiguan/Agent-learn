Notebook 与 Zotero：先保证来源可回到原位置

身份分支选读

带引用的问答工具中创建一个项目，只添加获授权资料，为每份资料记录名称和版本；提问时限定当前来源，要求区分支持、未支持与推断。打开 citation 后核对段落前后条件；把引用位置和判断写入自己的证据表。工具回答很确定却没有支持段落时，正确结果是未支持，而不是继续问到它同意为止。上传、共享与删除分别检查范围；课堂演示材料可全部使用本地原创文本。

Zotero 的顺序是：新建 collection → 添加条目或用标识符导入 → 核对作者年份题名 → 附 PDF → 写带页/节定位的笔记 → 用 tag 标已核/待核 → 生成引用与书目。一个 PDF 不是完整的书目条目，抓取元数据后仍要核对。遇到重复条目先检查是否同一版本，再合并；删除 collection 与删除库条目不是同义操作。协作前检查共享的是条目还是附件，以及附件的授权。

本地也能练同一方法：reference-work 的每项 question 都有 location、evidence、judgment，这些字段对应证据管理，不依赖注册服务。

最小可复现实验：代码、数据、指标分开

身份分支选读

本例练习怎样记录重跑实验所需的条件，没有复现 Transformer。三行虚构数据中有两行正确，预期指标是 count=3、accuracy 约 0.6667。完整代码如下：

"""固定虚构数据的可复现实验，不是论文训练结果。"""

# 从同目录读取各题的 correct 标记，计算样本数与准确率，再保存指标；它没有训练或评估新模型。
import csv
import json
from pathlib import Path

rows=list(csv.DictReader(Path('data.csv').open()))
values=[int(row['correct']) for row in rows]
if not values or any(value not in (0,1) for value in values):
    raise ValueError('correct 必须为0或1，且至少一行')
# 将当前产物保存到明确文件，供另一次运行或人工复核；保存成功本身不代表内容已通过验收。
# 以 JSON 保留字段和类型，便于重跑比较或人工核对；不能只保存对象的调试显示。
# indent：给本地 JSON 产物增加缩进，方便人工逐字段检查；不会改变数据内容。
Path('metrics.json').write_text(json.dumps({'count':len(values),'accuracy':sum(values)/len(values)},indent=2))
# 读取实际文件作为本次依据，避免使用对旧版本内容的猜测；读到的文字仍只是数据。
print(Path('metrics.json').read_text())

可选 DVC 路径：完整管线

扩展选读

仅在需要数据版本和管线复现时选做。

DVC 负责将数据版本与代码版本关联，不负责证明研究正确。下面在新副本中运行，安装也使用独立环境。若已经初始化，不重复 init。

# 切换到 /tmp/course-repro-demo，让后面的相对路径从这里开始计算；已在该目录时可跳过。
cd /tmp/course-repro-demo
# 用指定 Python 创建独立虚拟环境，避免本例依赖与其他课程互相影响。
python3.11 -m venv .venv
# 在所用环境中安装本例列出的依赖及版本；这不会下载课程正文。
.venv/bin/python -m pip install dvc
# 在本例独立演示目录初始化版本记录。
git init
# 按本行参数管理数据版本或重跑实验阶段。
.venv/bin/dvc init
# 按本行参数管理数据版本或重跑实验阶段。
.venv/bin/dvc add data.csv
# 在当前终端激活指定虚拟环境，让后面的 python 使用该环境中的解释器与依赖。
source .venv/bin/activate
# 按本行参数管理数据版本或重跑实验阶段。
dvc repro
# 按本行参数管理数据版本或重跑实验阶段。
dvc metrics show

source 在此用于让 dvc.yaml 里的 python 指向刚创建的解释器。配置文件如下：

# 列出 DVC 可重跑的处理阶段。
stages:
  # 将指标计算阶段命名为 measure。
  measure:
    # 重跑此阶段使用当前环境中的 Python。
    # 重跑时用当前 Python 环境执行指标脚本。
    cmd: python measure.py
    # 这些输入或脚本变化时，DVC 才需要重新计算对应指标。
    # 列出阶段依赖；这些内容变化时需重新计算。
    deps:
      # 把输入样本表纳入依赖。
      - data.csv
      # 把指标计算代码纳入依赖。
      - measure.py
    # 将 JSON 标记为指标文件，便于比较不同数据版本的结果。
    # 声明阶段产出的指标文件。
    metrics:
      # 将 metrics.json 作为比较实验结果的指标文件。
      - metrics.json:
          # 不把此指标文件放入 DVC 数据缓存，保留为便于版本比较的小文本文件。
          cache: false

第一次执行会生成锁文件及指标；不改输入再 repro 不应重复无关步骤。改数据后应重算相关阶段。提交代码、DVC 元数据与锁文件时不要把整个 .venv 或数据 cache 加进 Git；remote 是另一项可选存储配置，课堂不要求上传。恢复旧 Git 版本后仍需让数据 checkout 到匹配版本，只有代码退回不是完整复现。

实验跟踪、发布与人工筛选

身份分支选读

实验跟踪记录每次运行的参数、代码版本、数据版本、环境、指标与产物；不同随机种子要有独立 run。对比时先看是否同一任务和指标，再看数字。日志中的高分不能替代方法审查。

发布到 Zenodo 等仓库前准备作品标题、作者、描述、版本、许可、关联代码与数据说明；明确哪些数据不能公开，以及可供复现的替代材料。发布是外部动作，不是本地运行脚本的默认下一步。课堂交付用本地 release-notes 也能练完整说明，不捏造 DOI。

文献筛选用预先说明的纳入/排除条件，记录逐项理由。工具排序只决定先看谁，不直接等于纳入决定。自动科学 Agent 的实验也应保存负结果与失败日志，不能让它只汇报最优一轮。

独立练习与参考标准

身份分支选读

提交两个数据版本、两次指标、对应代码与环境说明。正确参考：原版本2/3，新版本3/3；说明分数变化来自 q2 标签的修改，不能据此判断模型能力提升。能从指定版本还原数据并重跑相同指标才通过；DVC 未执行时只完成标准库路径，报告中分开标记。
