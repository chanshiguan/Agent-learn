## Stage 4：原小节覆盖

原文件：https://github.com/WenyuChiou/awesome-agentic-ai-zh/blob/main/stages/04-agent-frameworks.zh-Hans.md

### 学习目标、术语、选择地图、进入条件

- 八词：Workflow/Graph、Framework、Agent、Orchestration、State、Checkpoint、Handoff、HITL。
- Loop 是单次任务内反复决策；Graph 组织节点、边、状态；Framework 是实现积木；Production orchestration 加入跨流程恢复/评测/观测。
- 两轴：程序预定路径/模型决定路径 × 单/多 Agent，四格会重叠。
- 多 Agent 的理由必须是任务独立性、工具/权限/context 隔离、可并行探索以及评测收益；增加角色也增加沟通、整合与故障点。
- 先修是 Stage3 schema→call→execute→result→answer；async/await 有帮助，不是第一题门槛。

### 五种协作方式与进阶工具模式

- Routing/Handoff、Sequential、Parallel、Supervisor–Worker、Debate/Peer Review 都要讲控制权、数据如何传递、停止与失败传播。
- Parallel 的延迟受最慢支路、限流、重试与合并控制，不能写固定 1/N 加速。
- Dynamic tool selection：先路由或检索少量工具；Tool composition：输出直接接下一工具；Tool-augmented retrieval：把检索器当工具。三者不必使用框架。
- 框架选择依据：状态/检查点/HITL 用 LangGraph；角色原型可用 CrewAI；SDK orchestration/handoff 可用 OpenAI Agents SDK；微软团队看 MAF。Bifrost/LiteLLM 是网关/适配基础设施，不是 Agent 框架。

### API 实现补充核对

- LangGraph `interrupt(value)` 需 JSON 可序列化 payload、checkpointer、thread_id；恢复 `graph.invoke(Command(resume=...), config)`。中断节点恢复会从节点头重跑，前置副作用须幂等或另拆节点；不要吞掉中断异常。`InMemorySaver` 只适合同进程，不代表重启恢复。来源：https://docs.langchain.com/oss/python/langgraph/interrupts 。
- Smolagents 默认 CodeAgent 会在本地执行代码，不能以“框架默认”作为安全性证明。官方列 Docker、E2B、Modal 等隔离；受限 Python interpreter 不是绝对安全。来源：https://huggingface.co/docs/smolagents/en/tutorials/secure_code_execution 。
- Pydantic AI 当前入口用 `Agent(..., output_type=Schema)`、`run_sync(...).output`，不是早期 result_type/result.data。Ollama 模型构造 `OpenAIChatModel(model_name, provider=OpenAIProvider(base_url=...,api_key=...))`，字段验证与来源验证分开。原例 constraints answer/confidence/sources 可直接检查。

## Stage 6：原小节覆盖

原文件：https://github.com/WenyuChiou/awesome-agentic-ai-zh/blob/main/stages/06-memory-rag.zh-Hans.md

### 核心概念与四种方案

- Retrieval/RAG/Embedding/VectorStore/Chunk/Reranking/Memory 七词。
- 小资料临时回答可long context；多文档按问题找证据用RAG；跨session状态用Memory；稳定改变行为才考虑fine-tuning。RAG/Memory通常不改变模型权重。
- 索引时 load→split→embed→store；查询时 retrieve→可选rerank→generate→cite/evaluate。
- Retriever不限定向量库，可BM25、SQL、搜索引擎；Hybrid RAG的控制流不等于Hybrid Search合并候选。

### 五道原练习

1. Embedding：相近/无关句向量、cosine排名；同模型与同维度；用真实embedding时说明首次下载，固定向量stub只能测试逻辑。
2. Chroma：collection、add/upsert、query、metadata、语义与关键词比较；Client内存、PersistentClient路径的持久化区别；默认embedding可能下载模型。
3. Chunking：原实际代码是固定长度+overlap、段落、Markdown标题三种；比较chunk数量/长度/完整性/命中，不能把标题切分叫semantic chunking。
4. 完整RAG：chunk→索引→top-k→带证据生成；引用必须真的对应返回片段；缺证据拒答；能运行不等于faithful。
5. Memory：提取一项偏好并搜索读回，原例临时store；综合项目另外要求跨重启持久化与删除。

综合项目：3–5份获授权小文档，回答来源、找不到拒答；只保存一项非敏感偏好；重启读回；用户能删除。

### 四份主必读

- LangChain Retrieval：知识库既可新建，也可接现成SQL/CRM；两步RAG可预测，Agentic更灵活且成本动态，Hybrid混合控制。Loader/Splitter/Embedding/VectorStore/Retriever各负不同职责。
- LlamaIndex concepts：Document、Node、Index、Retriever、Response Synthesizer、Query Engine、Router、Agent/Workflow；ingestion和query阶段分开；索引不是模型训练。
- Chroma getting started：pip安装、Client、create_collection、add、query；documents和embeddings可自行提供；默认embedding函数和持久化应显式说清。
- LangGraph Agentic RAG：文档加载/切分/索引、retriever tool、模型决定检索、grade documents、rewrite question、generate；循环需另设界限，grader是模型判断不等于事实真值。

### 进阶 RAG（直接支线，必须本地解释）

- 故障定位：候选找不到/排序差/证据不够/生成违背证据；先看检索再看生成。
- 指标：Recall@k=找到相关数/相关总数；Hit@k按题至少1条相关；MRR看第一相关排名；nDCG考虑相关等级与位置；Faithfulness是是否被给定证据支持，不是世界事实全对。
- 固定baseline、同数据比较、20–50人工核对题；分别记录检索质量、答案、成本、延迟；原实验A纯向量/B混合/C重排。
- 切分：fixed、paragraph/headings、parent-child、semantic的不同机制；metadata/权限过滤必须检索前完成。
- BM25给词频/稀有词/长度归一，dense给语义；RRF按排名融合，不能直接加不同尺度原分数；reranker只能重排已有候选。
- Query transformation：Multi-query/HyDE/RAG Fusion/Decomposition；假想答案不是证据，查询数量要限。
- GraphRAG实体关系/社区主题与local/global查询；索引成本、错误关系传播；LightRAG不是同一产品；Microsoft GraphRAG官方标largely maintenance mode。
- Self-RAG是含训练反思token的方法，不等于随手追加“反思一下”；CRAG按retrieval evaluator置信分correct/incorrect/ambiguous，可能知识精炼/网页补救；Adaptive-RAG依复杂度选不检索/单步/多步。
- RAPTOR递归embedding+聚类+摘要成树，多层检索；教学摘要树若无原聚类/训练/数据不能叫论文完整复现。
- DSPy用signature/module/metric与示例优化提示/演示，部分方法可调权重；需分训练/验证/测试，不能拿holdout调prompt。
- Contextual Retrieval：给每个片段补文档局部背景，再同时建contextual dense和BM25索引，可加rerank；prompt caching帮助重复长文档的预处理成本。原49%/67%是特定benchmark检索失败率相对降幅，不是通用准确率。
- Qdrant Hybrid Queries：多路prefetch→fusion/rerank；Weaviate Hybrid：BM25F+vector，以alpha权重和融合策略控制；这些是产品API，不同于自己写的示意排名程序。

### Agent Memory（直接支线，必须本地解释）

- Chat history是记录；context是当前模型看到的材料；RAG是外部证据；memory是未来要再用的状态。
- 短期/长期按作用范围，非RAM/磁盘；semantic事实、episodic经历、procedural规则；semantic memory不等于semantic search。
- 生命周期：建议保存→允许→规范化→metadata→用户/workspace隔离→相关检索→更新冲突→删除/过期；source/owner/time/version/sensitivity不可缺。
- 固定字段用表；自由经验可文本搜索；关系时间复杂才图；同线程恢复用checkpoint，不要滥用长期memory。
- Hot path实时更新增加延迟；background异步需处理重试/晚到更新/冲突；取回内容仍是不可信数据。
- 测试add/search/update/delete/isolation，外加过期/重启/冲突/缓存删除路径；只验证add不够。
- LangGraph：checkpointer负责thread；store负责跨thread namespace；`InMemoryStore`并不跨进程持久。CoALA是认知架构分类，不是pip库。
- Generative Agents：经验流、recency/importance/relevance取回、reflection形成较高层认识、planning/reacting；25人小镇的believability研究，不是生产正确性评测。
- Mem0/Letta Code/LangMem/Graphiti等是实现选择，供应商benchmark不能替代自己的隔离/删除/检索测试；Letta入口现为landing，source在letta-code；Zep repo是Cloud例子，非旧CE服务器。
