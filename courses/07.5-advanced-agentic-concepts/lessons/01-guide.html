本课不是新框架安装课

主线必读

原课程这一站是阅读与决策，先修是第七课的可重跑评测、停止条件和单 Agent 基线。正文当前讲四个核心概念，README 旧的“十二个”不是本课编号依据。本地补充脚本演示怎样按事先约定的标准作决定。完成本课不需要购买 API，也不需要训练模型。

1. Evaluator-Optimizer：反馈必须可验证

主线必读

生成器写产物，检查者按 rubric 指出差距，生成器有限次数修改。适合“什么叫更好”可说明的任务，例如引用完整、格式正确、遗漏条款减少。如果只能说“感觉不够好”，却说不清评价标准，让模型互相点评也很难可靠地改进结果。

Judge 也会偏爱某种措辞、长答案或自己的风格。准备人工标注样本，看它会不会把无依据但流畅的答案打高分。评价标准不应偷偷包含参考答案供生成器照抄。限制修改轮数，质量变差时保留旧版本。

2. Failure Injection：主动制造小故障

主线必读

只在隔离的测试环境里模拟超时、工具不可用、坏 JSON、陈旧资料、丢失批准、半写入状态。检查系统能否停止、说明问题、保留证据、正确恢复。它不是去破坏真实数据库或向真实账户发送测试消息。

把正常输入与故障输入配成对照；一次只注入一种故障，才能定位原因。测试报告区分模型选择错、程序逻辑错、基础设施不可用。看到程序“没有崩溃”还不够，失败后不能偷偷产生副作用。

3. Autonomy Gradients：权限随风险变化

主线必读

可以让 Agent 建议、产生待审草稿、在受限环境执行，或在充分验证后执行部分低风险动作。这些层级是一种设计方法，并没有全球统一的划分标准。权限由可信系统发放，不能由模型自报“置信度高”升级。

风险看数据敏感性、动作可逆性、影响范围、可检测性与恢复难度。写一个本地草稿与向客户发送邮件不属于同一级。越权检测、隔离、批准、审计和回滚不因模型变强而消失。

4. Model–Harness Fit：模型升级后重做删除实验

主线必读

有些步骤是为弱模型补短板，例如重复格式修复、先翻译再回答、复杂路由。换模型后逐个移除，用同一套题检查质量、成本、延迟和安全要求是否仍然满足。不能一次删五项后宣称知道哪项多余。

Keep：仍有清楚收益；Simplify：保留责任但减少实现步骤；Remove：没有必要收益且不承担不可缺的控制责任。删除一个 Prompt 修补环节，与删除权限检查不是同一性质。

5. 其他模式的证据门槛

必读概念 · 实作按需

选择方法的证据门槛必读；所列复杂模式不要求逐个实现。

并行探索要求子问题能够独立处理，结果能够合并；层级委派需要清晰职责和总任务上限；handoff 需要明确控制权和数据交接；plan-act-reflect 需要真实环境反馈而非空泛反思；dynamic workflow 适合可以写成可重跑脚本的分工。

如果多个分支共享大量隐含上下文，拆分可能增加沟通成本。每条消息都“简洁”也可能丢关键约束。先把接口、共享事实、冲突处理与最终责任写出来，再决定并行。

6. 一张决策记录

主线必读

必须写五项：失败案例与证据；baseline 的质量/成本/时延/安全；唯一拟增加或移除的步骤；事前接受门槛；停止或撤销办法。缺一项就先补实验，不靠“最近大家都在用”。

例如十题中两题缺引用，候选方案加引用检查。门槛可以是缺引用不增加、事实错误不增加、延迟不超过基线 1.2 倍；这些数值是你为自己的任务选的，不是通用标准。固定教学脚本 examples/decision.py 示范门槛判定，输出只说“可继续验证”，不是凭一组数字直接准许上线。
