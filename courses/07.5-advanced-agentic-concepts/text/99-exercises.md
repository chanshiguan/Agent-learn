# 第 7.5 课课后练习

## 目的与交付

目的：学会拒绝没有证据的复杂化。交付一份 decision.md，不强制写 Agent 或购买 API。完成后你应能根据可重现失败提出一个改动，并在无收益时撤回。

## 贯穿练习

从第七课选择一个真实失败。写清 outcome 和 trajectory；记录 baseline；从四个核心概念中选择一个改法；事前写接受门槛；列出撤销步骤。若没有真实失败，不编造收益：先提出待验证假设，标为“尚未采用”。

再做两个反例：候选方案质量略高但越权一次，应拒绝；质量不降而 token 减半，但删除了必要人工审批，也不能直接采用。安全约束和质量指标不是随意互相抵消的分数。

## 本课分层完成标准

1. 先回想：不看答案，用自己的话解释本课几个容易混淆的概念，再展开答案核对。
2. 跟着做：按[分步实作与完整参考](03-workshop.md)运行最小案例，保存输入和输出。
3. 自己做：换一份资料，或修改一个要求，完成自己的结果。只运行参考文件还不够。
4. 试着排错：故意触发一次失败，说明怎么找到原因、怎么修复，再运行正常例子确认恢复。

做完后，对照实作章末尾的评分标准逐项检查。分别记录代码是否运行成功、自动检查是否通过、内容是否经过人工核对，以及实际集成是否完成。待复核和未执行的项目暂不计为通过。卡住时，把课程编号、输入和实际输出发给我，一起定位问题。完成练习所需的步骤都在项目里。
