结业 A：做一条你会反复使用的 CLI 工作流

把 A1、A2、第五课核心和 A3 的能力用在同一个任务中。先跑固定的会议整理示范，理解完整交付长什么样；再换自己的资料独立完成，并按五维标准自评。第八课建议学习，但不是本结业项目的强制前提。

原课门槛

A 线必读

共用基础、A1、A2、第五课核心 5.1–5.4、A3 通过自我检查；第五课扩展和第八课不影响进入，第八课建议学习。选择一个真实重复问题，用 CLI Agent 为核心，至少连接一个 MCP 或自写 Skill/command。

成品必须有明确输入、可用产出、别人可重跑的说明和至少一种失败处理。仅写一个离线 Python 脚本不满足 CLI Agent 核心要求；仅跟模型聊天没有交付物也不满足。

完整示范：会议资料到行动草稿

A 线必读

输入 meeting.txt，流程由 meeting-actions Skill 规定，CLI 生成 JSON 草稿，人核对后保存 draft.json，validate.py 做独立检查。输出不发送、不写真实日历。真实任务中换成你有权使用的资料，保持待确认和引用规则。

examples 包含 Skill、任务卡、虚构资料、参考产物与完整验证器。把该目录复制到干净 demo；按所用宿主规则将 Skill 放入项目级技能目录，或在交互式 CLI 中显式提供它作为操作步骤。放好文件后，还要检查宿主是否真正识别并加载了 Skill。

在当前 CLI 会话提交 task.md，确认它读取了正确 Skill 与资料。把实际结果另存 draft.json，然后运行：

# 运行 courses/capstone-a/examples/validate.py，按本行参数完成当前案例并核对输出。
.venv/bin/python courses/capstone-a/examples/validate.py /tmp/draft.json

使用你的实际输出路径。默认不带路径时只校验 reference-draft.json，不能拿那次 PASS 当真实 CLI 成绩。保留 CLI 版本、模型、实际输出、检查日志和一次失败；缺文件时应停止，不生成替代会议内容。

五维四级自评

A 线必读

从五个方面自评：问题是否真实、工具运用是否合适、别人能否重跑、失败后能否处理，以及文档与反思是否完整。每项分四级：未达，表示缺失或无法使用；基本，表示能运行但条件没有说清；良好，表示有真实用途、完整步骤和失败处理；优秀，还要有可测量的收益、可重复验证的结果和明确改进。原课完整 rubric 已放在本地核对资料中。

最终交付

A 线必读

一个目录，含成品、README、至少一次真实 CLI 运行证据、150 字以内反思。README 写安装、设置、输入、执行、预期输出、失败和卸载。省了多少时间应来自测量，不靠估计写成事实。
