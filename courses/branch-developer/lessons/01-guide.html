从真实 diff 出发

身份分支选读

本分支推荐 A1→A2→第五课核心→A3；从 B 线过来可先看第七课。每次修改都要围绕一个明确问题，只改解决问题所需的部分，运行相关检查，并知道怎样撤回。

Context 是任务所需资料，Harness 管运行，Skill 复用流程，MCP 接工具，Subagent 分离上下文，Worktree 隔离工作目录，Eval 验证表现，Review 检查变更影响。OpenRouter 是模型入口，Ollama 是本地服务，Pi/OpenCode 等是运行工具，不是同一类替代品。

原练习：只改一份 README

身份分支选读

先读取 README、项目规则和相关测试说明，提出只涉及一份文档的计划。用户确认后修改，查看 diff，运行仓库文档检查或最小相关检查，最后说明如何只撤回这次改动。不要因为“顺手”重排整份文档。

在本地例子中 input.json 表示尚未修改、尚未测试的状态。正确结果应提出计划并列出缺少的 diff 与测试证据，不能写“全部检查通过”。完整可操作 demo 在 A1；本课练习重点是审查计划和证据。

每日开发

身份分支选读

给问题的触发条件、实际结果、期望结果和最小复现。先定位，再改动，再验证。Bug 修复要用能复现问题的检查验证；文档小改不需要为了形式新增大量测试。引用具体文件与行，说明新行为和影响范围。

PR Review

身份分支选读

优先检查正确性、数据损坏风险、权限、兼容性，以及是否缺少必要验证。审查意见要写清触发场景、影响和位置；个人风格偏好与必须修复的错误分开说明。只看新增行可能漏掉调用者约定，要阅读必要上下文；但不扩展成无关全仓重构。

CI 与批量重构

身份分支选读

CI 把规则变成可重复反馈；最小权限、可信依赖和隔离执行仍重要。批量重构先小样本，确认 API 契约与测试，再分批推进，每批都有 diff 与回退点。类型检查通过不能证明业务等价。

委派时分配独立文件或模块，明确公共接口与合并者。多个 Agent 不会自动解决并发冲突。Worktree 不等于进程沙箱；它避免文件混杂，不自动隔离凭证。
