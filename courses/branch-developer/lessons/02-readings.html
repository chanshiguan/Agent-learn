工具的官方工作流建议

身份分支选读

规则提供代码库地图，仓库资料提供约束，测试与运行反馈提供证据。先让 Agent 读取当前实现而不是凭记忆生成替代版本。长任务保留进度、版本和验证方式，下一次先确认现状。

Harness Engineering

身份分支选读

将架构约束、依赖方向和质量要求变成检查，比只写自然语言更稳定。规则文件保持短，深入说明放相应目录；文档本身也要检查是否过时。自动化越强，反馈、审计和恢复设施越重要。

代码审查与可回滚

身份分支选读

小改容易理解与撤回。记录原始问题、实际 diff、测试范围和未测边界，帮助别人复现。不要把“没发现问题”说成“证明没有问题”。没有运行的测试应写未运行及原因。

项目目录

身份分支选读

编辑器/CLI、模型路由、代码搜索、远程执行、评测和团队协作各承担不同职责。选择先看与仓库语言、权限、测试和交付流程是否匹配，而不是工具榜单。原课全部推荐项目及限制在本地核对资料中保留。
