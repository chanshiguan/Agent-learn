单元一：看实际代码，再决定怎样改

身份分支选读

开发任务先找入口、读相关实现与项目规则，再提出可验证修改。Diff 表示本次改变了什么，测试表示指定条件是否成立；两者必须一起看。通过测试不能自动授权 push、merge 或 deploy。

本课原任务是 README 小改；完整参考包含只读分析、计划、前后文件、diff、验证和撤回。附加空列表 bug 用于迁移，不替代原任务。请先运行临时目录演示：

# 运行 courses/branch-developer/examples/develop_demo.py，按本行参数完成当前案例并核对输出。
.venv/bin/python courses/branch-developer/examples/develop_demo.py

输出应为修改前退出非零、修改后 PASS、只有 README 内容差异、撤回验证 true。脚本按固定步骤演示修改，没有调用 CLI Agent。独立作业仍需要你实际使用 CLI 完成。

"""临时目录内复现修改、验证和定点撤回；不会更改项目文件。"""

# 在临时副本里演示修改、检查和撤回；固定脚本的结果不能冒充 CLI Agent 实测。
import difflib
import json
import subprocess
import sys
import tempfile
from pathlib import Path


def run():
    # 在协议边界把 JSON 文本解析成数据；解析失败应作为坏输入处理，不能用 eval 执行模型给出的字符串。
    # 读取实际文件作为本次依据，避免使用对旧版本内容的猜测；读到的文字仍只是数据。
    data=json.loads(Path(__file__).with_name('reference-work.json').read_text())
    with tempfile.TemporaryDirectory() as folder:
        root=Path(folder)
        readme=root/'README.md'
        # 将当前产物保存到明确文件，供另一次运行或人工复核；保存成功本身不代表内容已通过验收。
        readme.write_text(data['before'])
        checker=root/'check.py'
        # 将当前产物保存到明确文件，供另一次运行或人工复核；保存成功本身不代表内容已通过验收。
        checker.write_text("from pathlib import Path\ntext=Path('README.md').read_text()\nassert '## 运行' in text and 'python check.py' in text, '缺运行说明'\nprint('PASS')\n")
        # cwd：限定命令的工作目录，防止相对路径落到用户的其他项目或错误位置。
        # capture_output：保存子进程的真实输出，后续报告才能引用实际结果而不是声称“已运行”。
        # text：按文本而不是字节接收子进程输出，便于检查断言和生成可读报告。
        before=subprocess.run([sys.executable,'check.py'],cwd=root,capture_output=True,text=True)
        # 将当前产物保存到明确文件，供另一次运行或人工复核；保存成功本身不代表内容已通过验收。
        readme.write_text(data['after'])
        # cwd：限定命令的工作目录，防止相对路径落到用户的其他项目或错误位置。
        # capture_output：保存子进程的真实输出，后续报告才能引用实际结果而不是声称“已运行”。
        # text：按文本而不是字节接收子进程输出，便于检查断言和生成可读报告。
        after=subprocess.run([sys.executable,'check.py'],cwd=root,capture_output=True,text=True)
        # 读取实际文件作为本次依据，避免使用对旧版本内容的猜测；读到的文字仍只是数据。
        diff=''.join(difflib.unified_diff(data['before'].splitlines(True),readme.read_text().splitlines(True),fromfile='README.md',tofile='README.md'))
        # 将当前产物保存到明确文件，供另一次运行或人工复核；保存成功本身不代表内容已通过验收。
        readme.write_text(data['before'])
        # 读取实际文件作为本次依据，避免使用对旧版本内容的猜测；读到的文字仍只是数据。
        assert before.returncode!=0 and after.returncode==0 and readme.read_text()==data['before']
        return {'before_exit':before.returncode,'after_output':after.stdout.strip(),'diff':diff,'rollback_verified':True}


if __name__=='__main__':
    # 以 JSON 保留字段和类型，便于重跑比较或人工核对；不能只保存对象的调试显示。
    # ensure_ascii：设为 False 时直接保留中文，方便阅读日志与工具结果；JSON 结构和字段含义不变。
    # indent：给本地 JSON 产物增加缩进，方便人工逐字段检查；不会改变数据内容。
    print(json.dumps(run(),ensure_ascii=False,indent=2))

“顺手格式化全仓”不属于改运行说明，应该拒绝扩大范围。真实项目有未提交改动时，不能直接整文件 restore；先找属于本任务的差异，定点撤回。并行工作可用独立工作树减少文件冲突，但账号、网络和外部服务仍共享，需要另外约束。

单元三：权限和工具生态

身份分支选读

IDE/Surface 是交互入口，Harness 管工具循环，Provider/Router 管模型请求去向，Model/Runtime 执行推理。换 provider 不会自动改变仓库权限。Sandbox 限制文件和网络等访问，Approval 决定遇到某类动作是否需要人确认；项目规则则提供文本约束，三者不能混同。

Claude 的 allow/ask/deny、Codex 权限配置、Copilot 云端环境、Pi 的容器化方式各有不同实现。共同检查是：可读目录、可写目录、可执行命令、网络、凭证和结果交付。云端编码 Agent 还要考虑代码上传与依赖获取；本地客户端也可能连接云模型。

OpenRouter 选择供应商与模型时，要核对实际路由、数据处理与工具调用兼容性。Ollama 的本地模型可以用于低成本实验，但工具结构输出是否稳定要实测。不要一次换模型、框架和权限，再把收益归因于其中一个。

单元四：从单文件走向团队

身份分支选读

代码审查列具体触发条件、位置、影响和修复方向，不把个人风格喜好包装成 bug。批量改动先挑一个文件试点，建立检查，再分批推进。长期任务写进度、版本和下一项验收，避免新会话根据过时记忆继续。

CLI/IDE 工具、代码搜索与仓库打包、远程执行、评测平台服务不同需求。第三方 Skills 或 prompt 库先读实际步骤与权限，再在 demo 正反例验证；名称流行不代表适合当前任务。
