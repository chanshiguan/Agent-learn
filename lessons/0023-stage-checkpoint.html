先制造一个可控的连接错误

下面的环境变量只对这一条命令生效，不会覆盖你之前配置的值。它故意指向未提供模型服务的端口：

运行并观察

# 仅给这次请求使用故意错误的本机地址；预期连接失败，不改动当前终端原有配置。
LLM_MODE=local LLM_MODEL=connection-check \
LLM_BASE_URL=http://127.0.0.1:1/v1 \
python first_chat.py --output data/output/connection-failure.json

预期出现连接失败提示。若这台机器恰好在该端口运行服务，换一个确认空闲的本机端口再试。该实验不应产生“成功回答”记录，也不需要重装 SDK。报错来自连接层，先看地址与服务。

再改一次正常问题

回到真实配置，只改变提问：

# 只更改提问并保存到新记录；连接成功后还要人工核对是否遵守“只提问”的要求。
python first_chat.py \
  --question "请提出一个适合讨论《狂人日记》的开放式问题，不给出答案。" \
  --output data/output/model-question.json

观察它是否只提出了问题。没遵守要求时，把现象记下来；这正是后面需要 Prompt 与评测的原因。不能因为 HTTP 成功，就把输出行为记为正确。

记录时分开写三件事

记录 示例含义
程序连接是否成功 收到了非空且正常结束的响应
输出是否符合本次要求 是否只提一个开放问题，没有自己作答
回答有没有资料依据 本阶段未发送讲稿，因此这项尚未实现

延迟和 token 用量也保留。一次测量只描述这次请求，不能直接推出 M1 的稳定并发量或哪种模型一定更好。两条路线比较时保持同一问题，分别保存记录，并明确哪些路径没有运行。

本单元验收与参考答案

先完成上面的操作，再用自己的话回答。下面是核对思路和结果的参考，不要求背原句。

查看参考答案与通过标准

换一份讲稿后为什么仍要保存来源？ 答案和读取结果将来要能回查文件与段落；指纹还能帮助判断是否换了输入版本。它不代替内容核查。

删掉练习容器后，到哪里找结果？ 去主机的 data/output/，因为运行时已把它绑定到容器 /output/。未挂载的容器内部文件不具备这种保留方式。

错误模型地址导致哪一层失败？ 本节故意指向未提供模型服务的端口，预期停在连接层，还没生成文学回答。无需为此重装 SDK；临时环境变量也不会覆盖原有配置。

开放问题的合格示例？ “你觉得文言文序言与白话日记给读者的距离感有何不同？”这只是教师拟写的行为示例，不是模型实测输出。实际答案只要是一个可讨论的问题、没有替读者作答即可；HTTP 成功但没遵守要求时，应分开记录。

模型读过五份讲稿了吗？ 没有。目前“读稿并保存 JSON”和“向模型发问题”是两条分开的流程；下一阶段才把资料接入请求，再加入检索。

**通过证据：**项目卡每行都指向本次实际文件或失败记录；资料核对记录、题单、两份主机 JSON、容器输出和真实模型记录可回查；错误连接按预期失败。隔天能独立画出两条流程并说出缺失连接，比记住命令更能说明理解。未实际运行的项继续标“待运行”。
