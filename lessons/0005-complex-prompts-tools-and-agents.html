Lesson 05 · Workflows

当 Prompt 越写越长，往往应该改流程了

复杂任务不只需要更多指令，还需要计划、分解、工具调用、验证和失败恢复。这一课把 Anthropic 复杂 Prompt 模板和附录、Google Agentic Workflow、OpenAI Agent 任务建议连起来。

1. 复杂 Prompt 的组件库

Anthropic 第 9 章将复杂 Prompt 拆成一组可选组件。不是每个 Prompt 都要包含全部组件，但它是一份完整检查清单：

组件回答什么问题客服 Agent 示例
Task context你是谁，总目标是什么？你是售后分流助手
Tone context用什么语气和对象沟通？简短、冷静、不责备用户
Task description具体职责和规则是什么？分类，必要时询问补充信息
Examples理想行为和边界是什么样？边界留言与期望输出
Input data这次处理的资料是什么？对话历史与当前留言
Immediate task现在这一步要做什么？判断应转给哪个队列
Planning/analysis需要哪些可检查处理步骤？先检查支付，再检查技术故障
Output formatting结果结构是什么？标签 + 简短可验证理由
Prefill需要给输出一个起点吗？<result>
构建顺序：先使用较完整的结构将任务做对，然后用 Eval 删减没有价值的组件。不要一开始就追求“最短神奇 Prompt”。

2. 顺序不是绝对，但要有理由

通用起点可以是：身份/任务背景 → 规则 → 范例 → 资料 → 当前任务 → 输出格式。对长文档，现代 Gemini 建议将大量上下文放在前面，具体问题放在文档后面，并用“根据上述资料”连接上下文和任务。

不同任务可以调整顺序，但每次调整都应用同一组 Eval 检查。

3. 三种拆分复杂度的方法

方法结构适合场景
路由/拆指令先识别任务类型，选择对应 Prompt客服、多种文档处理
链式处理A 的输出成为 B 的输入提取证据 → 写答案 → 审核
并行后聚合分片处理，再合并结果多文档摘要、多维度评审

链式处理还可以用于修订：第一次生成草稿，第二次检查事实或风格，第三次输出定稿。但“再检查一次”也可能改坏原本正确的答案，所以要允许审核器回答“无需修改”。

4. 工具调用的不变本质

模型选工具与参数→生成暂停→程序执行工具→工具结果返回模型→模型继续

工具可以是计算器、天气 API、SQL 查询、搜索、文件读写或业务操作。模型不是自己在操作数据库；它只是产生一个结构化的工具请求，真正的代码决定是否执行。

历史内容警告：Anthropic 附录使用 XML 文本自己实现 function calling，并明确说当时还将改进。这种方式可以用来理解原理，但现在应优先使用供应商的原生 Tool/Function Schema，不要自己用正则表达式解析模型生成的伪函数调用。

5. 工具定义要说清什么

  • 工具名称与精确用途。
  • 什么情况该用，什么情况不该用。
  • 每个参数的类型、含义、是否必填和合法值。
  • 工具结果的结构和可能错误。
  • 写操作、高风险操作和权限边界。

对 SQL 或数据库工具，还要区分读取与写入，不要让“查用户”和“创建用户”共用模糊的参数说明。

6. 从 Prompt 链到 Agent Loop

while 任务未完成:
    让模型根据当前状态选择下一步
    if 模型请求工具:
        检查权限和参数
        执行工具
        追加工具结果
    else:
        验证最终答案
        结束

Agent 不只是“带工具的聊天”。一个可靠 Agent 需要明确三组行为维度：

维度关键决策
推理与策略怎样分解任务，诊断多深，查阅资料多全面
执行与可靠性观察变化后是否转向，失败后重试多久，如何评估风险
交互与输出什么时候可做假设，什么时候问用户，进度说多少，结果需多精确

7. 计划、持续性和完成条件

OpenAI 对长时间 Agent 任务的建议是：在重要工具调用前提供简短说明，将任务拆成可跟踪项，并在每次观察后检查是否真正完成。重点不是“写一个超长计划”，而是防止只完成一半就停止。

完成条件应可验证：“修好代码”太弱；“失败测试先变红，修复后变绿，全部回归通过”才可检查。

8. 应对障碍：重试不等于原样重复

  • 短暂网络失败：在有限次数内重试。
  • 参数无效：修改参数或重新读取 schema，不要原样重试。
  • 权限不足：停止并向用户说明，不尝试绕过。
  • 假设被否定：生成新假设，而不是对旧结论继续加强语气。

9. 编程和前端 Agent 的特定要求

对编程任务，明确角色和工作流，给工具调用示例，要求运行测试并检查补丁是否真正应用。对前端任务，还应说明视觉标准、字体、色彩、间距、交互状态、可访问性、文件结构和 API 边界。

OpenAI 当前文档举例推荐 Tailwind CSS、shadcn/ui、Radix Themes、Lucide/Material Symbols/Heroicons 和 Motion。这是特定时期的工具建议，不是 Prompt Engineering 的永久定律；实际项目应匹配现有技术栈。
