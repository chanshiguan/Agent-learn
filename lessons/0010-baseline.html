建立一份小题单

上一节已经找到讲稿中的解释和引句，也确认材料没有纸质版本的页码。现在把这些观察变成以后用来检查助手的问题。

在 classics-reader 中创建 reading-questions.md，写下下面四题。这里标注的是希望怎样检查，不是程序已经做到的结果。

问题 以后怎样检查
第一讲怎样解释文言文序言与白话日记的区别？ 应找到第一讲，并说明这是讲稿的解释
第二讲和第四讲分别怎样解释狂人的观察？ 需要两份讲稿，不能只有流畅的概括
请给出这套讲稿所用原著版本的准确页码 若没有版本与页码资料，应说明无法确认
有人对人物作出另一种解释，能否讨论？ 区分文本依据与观点，不把某一讲稿当成唯一允许的理解

读过讲稿后，可展开导学四题的参考答案核对依据；先尝试独立回答。

再写第5题：从你刚打开的讲稿里选一个想问的问题，并记录可能支持回答的文件名和定位词。不确定证据时标“待核对”。建立评测题集时，会重新打开这份文件，把这道题写进程序能读取的题集。

前四题用来观察不同能力：单份资料、跨资料比较、缺资料拒答和开放讨论。后面不会把它们都用一个分数判断。你已看过这些问题，它们属于开发练习；不能再当作从未见过的测试题。

做一次不计分的基础诊断

打开终端，分别运行下面三行。先看每一行的结果，再运行下一行。

运行并观察

# 查看新终端当前所在的目录；此处还没有切换目录，显示主目录也是正常的。
pwd
# 检查终端能否找到 Python；这里只显示版本，不会安装或修改环境。
python3 --version
# 检查 Docker 客户端是否可找到；看到版本号还不能证明后台引擎可用。
docker --version

pwd 显示当前位置，后面会用它解释相对路径。版本命令只检查工具能否找到，不会安装软件。docker: command not found 表示还没找到 Docker 命令；它不代表你没有编程能力，也不妨碍先学第一章。

在项目卡末尾增加“环境检查”，记下这三条命令的实际输出；下一节会用 Python 版本决定是否需要安装，第2章再处理 Docker。现在不因为缺少工具就判定失败。再回答：“我能否独立创建一个文件、进入它所在的目录并运行程序？”如果不能，把具体卡住的一步记下来。后续按这个缺口补习，不用把全部基础重新学一遍。

导学交付

现在从 classics-reader 分别打开项目卡、五份讲稿和题单，确认记录都保存在同一个项目内。资料来源与定位词就在项目卡的“资料核对”中，不需要另外猜一个清单文件。

下一节先看“环境检查”，准备读取讲稿所需的 Python。之后会用第一讲和刚记下的定位词，核对你的第一个程序。

回忆练习：为什么现在不把整个知识库都装进去

先用少量确定的输入，才容易发现错误出在哪一步。比如第一讲读取失败，你可以直接打开它核对。若同时导入几千份文件，重复、格式、切分和模型问题可能混在一起。小样本跑稳后再扩大范围，学习过程更容易追踪。

**进入第一章前：**你能说明当前目标、找到样本，并保留自己的问题。你不需要已经会 Docker 或模型 API。

本单元验收与参考答案

先完成上面的操作，再用自己的话回答。下面是核对思路和结果的参考，不要求背原句。

查看参考答案与通过标准

为什么先用五份样本？ 输入少且已知，出错时可以逐份回查，更容易判断是文件、读取程序还是后续模型环节的问题。

题单里的问题现在要怎样回答？ 第一题比较序言整理者的外部叙述与白话日记的内部感受；第二题对照第二讲的月光、目光解读与第四讲对观察和推断的区分，必须同时回查两讲；第三题若缺少原著版本和页码，应答“现有资料不足，无法确认”；第四题允许讨论不同理解，但要区分文本证据与观点。

基础诊断怎么看？ pwd 返回工作目录；版本命令返回版本表示命令可找到；command not found 只说明工具还没准备好。Docker 未安装不妨碍先学第一章。

**通过证据：**项目卡中的资料记录、五份样本、含四道示例题及一道自拟题的题单都能找到。能指出第5题的候选文件和定位词，或说明还缺什么证据。没有写出前两题的文学答案，不算本单元未完成。
