试用先小到能够认真处理问题

在公司允许的受保护环境中开放有限账号、限定作品与时间窗口。准备一个负责人能接到的反馈入口，并说明什么情况立即停止试用：越权、错误写入、无法解释的资料泄露、严重内容问题或不能恢复的数据损坏。

把每个问题记录为：读者角色、操作步骤、期望、实际、trace_id、版本、影响范围、负责人、修复与复测。记录中不粘贴密钥，也尽量不复制私人对话。需要内容证据时按受控方式保存最少片段。

写一页真正用得上的操作手册

在项目根目录新建 RUNBOOK.md。它给接手项目的人使用：对方遇到故障时，应能沿着这份文件找到已经验证的操作，而不必重新读完课程。

按下面四部分写，每项都填你的真实命令或报告路径，不能只写“参考教程”：

  1. 启动与检查：第25章的启动、就绪检查、登录与问答验证；注明运行目录、所用镜像和凭据从哪里受控取得，文件中不写密钥。
  2. 失败与撤回：第23章用 trace 定位错误的方法、第27章的版本切换步骤；注明什么情况停止服务、由谁处理。
  3. 资料与数据：第27章的资料发布、第28章已实际完成的备份和恢复命令；单列删除账本等仍未实现的项目。
  4. 交接记录：链接本次 release/acceptance-candidate-01.json、未关闭问题和确认过的联系人。没有真实值班人就写“待安排”。

完成后，请另一位开发者按手册走一次“启动→问答→停止→恢复”，把需要口头补充的地方写回手册。这份运行结果会决定项目是否具备交接条件；尚无人复核时保留待验证。

运行并观察

# 从实际运行的候选容器生成交接清单，避免误用主机环境的依赖记录。
docker compose --env-file .env -f deploy/compose.yaml run --rm app python -m companion manifest
# 在独立测试目录重跑行为回归；它不替代试用反馈、真实模型质量或公司批准。
READING_DATA_DIR=data/test-state python -m unittest discover -s tests -v

完成一次修复→复测→小范围重新验证，再由相应负责人决定继续试用、正式放行或继续阻塞。没有公司环境时，可以完成模拟演练并明确标“模拟”，不能伪造真实用户、审批或上线结果。

结业迁移练习

从知识库再选一部有权使用的作品，小批导入独立目录。先核对它是原文、讲稿还是混合材料，再建新题集，保持用户与作品隔离。不要只改一个 book 标签就假设《三国演义》的章回、人物和剧透规则与《狂人日记》相同。

完成后再按需要选读 MCP、GraphRAG 或多 Agent。你应能先说出当前哪种失败需要新能力，再决定引入；不必把所有技术都塞进伴读助手。

什么才算这一轮项目交付完成？

可重跑的程序与资料流程、可回查测试证据、明确问题清单和操作交接完成；正式上线还需实际公司条件与授权满足。

换一本书时最先验证什么？

资料类型、来源版本、作品结构与读者问题，而不是先换模型。新范围需要新的评测与内容审核。

**通过证据：**受控试用或明确标注的模拟记录、一次修复复测闭环、可执行操作手册和真实放行/阻塞结论。

下次开始前

隔一天，先不看命令，解释本单元解决了什么问题，以及哪种情况仍会失败。再用你自己的一个阅读问题重跑关键步骤。若卡住，带上单元名称、预期结果和去掉凭据的错误信息继续讨论。

遇到问题时，可以带着本单元名称、写到的文件、预期和实际结果继续问我。不要附密钥；也不用为了继续往后走而跳过失败。

运行位置：你从导学开始创建的 classics-reader/ 项目根目录。主机统一使用全局 Python 3.12；新终端核对版本，并重新设置所选模型路线的环境变量。
