Lesson 04 · Reliability

错答时，先判断是“没想清”还是“没有资料”

推理、上下文、引用、搜索和代码执行解决的不是同一类问题。如果不先诊断失败类型，就会不断“优化 Prompt”却没有实质改善。

1. 四类常见失败

失败典型现象优先解法
任务理解错误答的是另一个问题重写目标、边界和输出
推理错误资料足够，但组合或判断错给可检查的步骤，或换更合适模型
知识/资料缺失询问实时事实或私有政策补上下文、检索或调工具
计算/执行错误算术、计数、查库或实际操作失败调计算器、代码执行或专用 API

2. 分步处理有用，但不应索要私有思维链

Anthropic 旧教程的第 6 章使用“让模型把思考全部说出来”改善复杂分类。这是当时的 Prompting 方法，但不能直接当成现代通用规则。

现代做法：推理模型可以在内部生成 thinking/reasoning token，不需要向用户公开全部内部思路。需要审查时，要求“给出简短理由、证据或可验证步骤”。

比如分类任务可以这样要求：

处理方法：
1. 检查是否与付款或发票有关。
2. 检查是否描述功能异常。
3. 都不符合时选 other。

输出：只返回最终标签。

这里提供的是可执行判断顺序，不是要求暴露无限长的私有推理。

3. 顺序偏差与选项敏感性

旧教程演示了正反两方观点的顺序可能影响结论。这不意味着“永远选第二个”，而是说 Prompt 本身也可能带有位置偏差。

可验证的方法是建立对称测试：把 A/B 顺序交换后再跑，检查结论是否发生不合理变化。

4. 幻觉是什么

幻觉是模型产生了不真实、无证据或不受资料支持的陈述。模型往往是为了显得有帮助而猜测，所以只说“请准确”不足以解决。

降低幻觉的四层方法

  1. 允许不知道：明确说“信息不足时说无法确定”。
  2. 先找证据：从文档提取支持结论的片段，再基于证据回答。
  3. 提供可靠上下文：将企业资料、说明书或搜索结果放入 Prompt。
  4. 使用工具：新闻、实时数据用搜索；数学、计数用代码执行。

5. Context 和 RAG

上下文是这次请求提供给模型的参考资料。RAG（检索增强生成）是先从向量库、文件、搜索系统或其他来源找到相关片段，再将它们放入模型上下文。

# Context
<manual>
缓慢闪烁黄灯：表示网络连接异常。
检查路由器与调制解调器的网线和电源。
</manual>

# Question
路由器正在缓慢闪黄灯，怎么处理？

# Rule
只使用 manual 中的信息；没写的信息说“资料中没有说明”。

上下文不是越多越好。模型有 context window 限制，大量无关资料会掩盖真正证据。要优先放相关、可信、有清晰边界的资料。

6. 先提取证据，再回答

对长文档问答，可以将流程拆成：

读问题→提取相关证据→检查证据是否足够→基于证据回答

证据不足时，输出“无法从资料确定”，而不是用相似但不相关的句子拼出结论。

7. Grounding 和代码执行

需求工具原因
当前新闻、价格、时间敏感信息搜索/Grounding模型训练知识不是实时数据库
精确算术、统计、计数计算器/代码执行语言生成不是数值运算引擎
公司内部规章文件检索/RAG模型未必看过该私有内容

工具不只是“额外能力”，也是可验证性的来源：计算结果、数据库行和搜索来源都可以被重复检查。

8. Temperature 和幻觉

旧 Anthropic 教程建议某些幻觉可以通过降低 temperature 减轻。它可以减少输出变化，却不会创造缺失的事实。而且新模型可能忽略自定义采样参数或建议保持默认。因此优先级是：资料与证据 > 任务规则 > 采样参数。

9. 检索练习

2. 资料中找不到答案时，最可靠的默认行为是？
