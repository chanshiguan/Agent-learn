确认程序和资料没有绑死在一起

本单元 20—30 分钟本章 70—100 分钟安装与下载等待另计选读不计入用时

本单元预计 20—30 分钟。第三章的最后一步，是验证镜像真的只负责程序，而资料通过运行时输入提供。

检查镜像里没有资料目录

# 临时改用 Python 检查镜像内是否已有资料目录；没有挂载时预期为 False。
docker run --rm --entrypoint python classics-reader:chapter3 \
  -c "from pathlib import Path; print('镜像内存在 /input：', Path('/input').exists())"

预期为 False。这次没有挂载资料，所以 /input 不会凭空出现。--entrypoint python 只是为检查临时改用 Python 作为启动程序，不会永久修改镜像。

然后做一次有意的失败：

# 故意不给镜像挂载输入资料；预期读取失败，随后查看退出码 2。
docker run --rm classics-reader:chapter3 /input/not-found.docx /tmp/result.json
# 立即检查上一条程序的退出状态；本节故意输入错误时预期为 2，中间不要执行其他命令。
echo $?

预期出现输入路径错误，退出码为 2。这说明程序需要你明确提供资料，没有偷偷从主机目录读取。

把结果写进实验记录

在 project-card.md 补上镜像名称、实际构建日期、输入文件、主机与镜像结果是否一致。没有实际运行的命令标为“待运行”。

这份镜像目前用于单人学习。它没有账号、访问控制或完整的部署配置，不能因为能启动就直接对外提供伴读服务。课程后面的发布阶段会继续补这些能力。

查看参考答案与通过标准

没有挂载时应看到什么？ 镜像内 /input 检查为 False；直接读取不存在的输入应报错并返回退出码 2。程序不会自动去主机寻找资料。

换讲稿、改代码各怎样做？ 换讲稿保持镜像不变，改输入参数和输出文件名；改代码重新 docker build，再用更新后的镜像运行。删除容器后，结果仍从主机 data/output/ 找。

把 /input 改成 /books，要改哪里？ 将挂载参数的 dst=/input 改为 dst=/books，同时将脚本输入改成 /books/完整文件名。主机的 src 可以不变。

**通过证据：**重开终端后能重新生成 image.json；记录输入指纹与对照结果。这个镜像还没有账号、权限或完整上线配置。
