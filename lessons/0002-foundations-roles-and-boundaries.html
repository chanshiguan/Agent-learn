Lesson 02 · Foundations

先把“信封”和“信的内容”分清

这一课要解决四个基础问题：返回值怎么取、模型怎么选、角色怎么分、动态资料怎么不与指令混在一起。

1. Prompt 不只是那句问话

一次模型请求至少有三层：

层它管什么例子
API 请求模型、token 上限、温度、工具等model、max_tokens
消息结构内容来自开发者、用户还是模型developer、user、assistant
Prompt 内容目标、资料、规则、范例和输出要求“只返回 billing/bug/other”

角色是信封上的“寄件人与优先级”，指令是信里写的内容。把 system 或 developer 当成 Prompt Engineering 技巧本身，会混淆这两层。

2. 先正确读取模型返回

OpenAI Responses API 的 output 可能同时包含文本、工具调用和推理信息，不应永远假设文本在 output[0].content[0].text。官方 SDK 提供 response.output_text 聚合文本输出。如果使用 Chat Completions 兼容接口，则常见于 response.choices[0].message.content。

# Responses API
response = client.responses.create(
    model="...",
    input="...",
)
print(response.output_text)
# Chat Completions 兼容接口
response = client.chat.completions.create(
    model="...",
    messages=[...],
)
print(response.choices[0].message.content)

严格 JSON 不应只靠“请返回 JSON”，有 schema 要求时应使用 Structured Outputs 或工具 schema。

3. 模型选择决定了 Prompt 的写法上限

类型优点代价Prompt 风格
大型推理模型复杂计划和多步问题强慢、贵、可能用更多推理 token给目标和关键约束，不必过度微管理
通用 GPT/生成模型快、成本低、适合明确任务更需要明确逻辑和格式把步骤、判断规则和输出说清
小模型本地、快、便宜边界理解和复杂任务较弱简短、明确、范例化，用 Eval 验证

因此，Prompt 不是脱离模型存在的万能文字。换模型后要重跑 Eval。

4. 消息角色和指令优先级

当前 OpenAI 结构可以理解为：

  • developer / instructions：应用提供的高层目标、业务规则、风格和范例。
  • user / input：用户本次的问题、数据和选项。
  • assistant：模型已经生成的历史内容，也可用于多轮示例。
容易忽略：Responses API 中的 instructions 只对当前请求生效。使用 previous_response_id 继续对话时，不能假设上一轮 instructions 自动继承。

一个很好的类比是：developer 像函数定义，user 像本次传入的参数。

5. 清晰直接：不要让模型猜

Anthropic 的“清晰 Prompt 黄金规则”是：把 Prompt 给一个不熟悉任务的人，如果他不知道怎么产生你想要的结果，模型也可能不知道。

模糊

“帮我写一个好一点的故事。”

可检查

“写一篇 600–800 字的儿童冒险故事，主角 10 岁，结尾解决冲突，不使用暴力。”

要求“只输出一个名字”、“使用西班牙语”、“超过 800 字”，都应该直接写出来，不要期待模型从语气推测。

6. 四种常见输入形态

形态例子适合的要求
问题 Question“为什么海水是咸的？”说明受众、深度、证据范围
任务 Task“把这段邮件改得更礼貌。”说明目标、约束、验收标准
实体 Entity只提供一个词、产品名或主题明确要对该实体执行什么操作
部分补全 Completion“商品：两个汉堡；数量 JSON：{”给出开头，引导模型续写目标格式

只给实体最容易产生歧义。例如输入“土星”时，模型不知道你要定义、翻译、写诗还是比较行星。输入形态越简略，任务说明越要完整。部分补全会在下一课详细讲。

7. 角色有用，但不是魔法

角色可以影响语气、专业视角、受众难度和处理任务时的偏好。“你是逻辑审查员”比“你是专家”更有信息，因为它说明了角色的具体职责。

角色最好同时说明：身份、目标、受众、边界。

# Identity
你是客服质量审核员。
你要帮助一线客服识别留言类别。
读者不熟悉技术术语。
不要猜测留言中没有提供的信息。

角色不能提供缺失的业务数据，也不能将小模型变成大模型。它只是结构化上下文的一种方法。

8. 将稳定指令与动态资料分开

当程序反复做同一任务时，应使用 Prompt Template：骨架固定，资料通过变量替换。

prompt = f"""
# Task
将留言分为 billing、bug 或 other。

# Input
<message>{message}</message>

# Output
只返回一个合法标签。
"""

XML 标签、Markdown 标题或明确分隔符的作用是表达边界。标签名没有必须背诵的“神奇口令”，关键是语义清晰且前后一致。

小细节会改变结果：错别字、破损列表、不一致分隔符和资料前的多余连字符，都可能让模型把资料误解为指令或列表项。
