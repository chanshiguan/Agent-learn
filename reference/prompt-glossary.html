Prompt Engineering 中文术语表

这里不是只给中文翻译，而是说明每个词在实际开发中解决什么问题。按概念关系分组，比按字母顺序更容易形成整体认识。

一、请求与消息结构

术语中文理解实际用途
Prompt一次发给模型的完整提示可以包含身份、规则、上下文、范例、当前输入和输出要求，不只是用户的一句话
Instruction告诉模型要做什么、怎么做的指令例如“分类”“只返回标签”“不确定时回答不知道”
Context完成任务所需的背景资料文档、对话历史、数据库记录、检索片段等；它不是默认可信，应标注来源
System message系统级行为与边界定义助手身份、长期规则、工具策略；具体优先级依 API 而异
Developer message应用开发者提供的高优先级规则OpenAI 当前消息层级中高于 user；适合应用逻辑和安全边界
User message本次用户目标和数据像调用函数时传入的参数，不能覆盖更高优先级规则
Assistant message模型之前的输出或预填开头可用于多轮历史；部分旧接口允许预填来引导格式
Role prompting给模型设定专业身份或交流角色主要影响关注点、语气和受众适配，不能凭空增加知识或权限
Prompt template稳定文本加动态变量的提示模板把业务规则与本次输入分离，便于复用、版本控制和测试
Delimiter输入边界标记用 XML 标签、Markdown 围栏等区分指令与不可信数据，减少歧义

二、范例与输出控制

术语中文理解实际用途
Zero-shot不给范例，直接说明任务先建立最小基线；简单或模型熟悉的任务往往已经够用
One-shot给一个输入输出范例快速示范格式或一个重要边界
Few-shot给少量代表性范例用行为示范补充规则；范例应多样、正确、格式一致并覆盖难点
Output format输出必须长什么样限定标签、字段、Markdown、XML 或 JSON；便于人读或程序解析
Structured Outputs按 schema 强约束结构化输出比只在文字里要求“返回 JSON”更可靠；仍要校验业务含义
Prefill预先提供助手回答的开头例如先写 { 引导 JSON；是否支持取决于模型和 API
Stop sequence遇到指定文本就停止生成控制生成边界；如果停止词可能出现在正文，会导致误截断
Completion模型对输入的续写结果早期 API 常用术语；现代响应还可能同时包含工具调用、推理项等
Fallback正常路径失败时的安全退路可指安全拒答，也可指超时、解析失败、工具失败或信息不足时的应用策略

三、模型生成与资源

术语中文理解实际用途
Token模型处理文本的基本片段输入、输出和某些推理 token 共同影响上下文上限、成本与延迟
Context window一次请求能处理的 token 总容量通常包括指令、历史、资料、工具结果和预留输出；大窗口不等于所有信息都相关
Max output tokens最大输出额度硬上限，不是目标长度；过小会造成截断或看似空响应
Finish reason生成为何结束用于区分正常结束、达到长度上限、触发停止词、工具调用或安全阻断
Temperature采样随机性的一个控制量支持情况和含义依模型而异；低值也不保证跨版本绝对一致
Top-k只保留概率最高的 K 个候选缩小采样集合；新模型可能不允许或不建议手动设置
Top-p保留累积概率达到阈值的候选集合又称 nucleus sampling；不要与其他参数无目的同时调整
Prompt caching复用相同请求前缀的计算结果把稳定规则和范例放前面、动态数据放后面，可降低部分成本和延迟
Model snapshot固定时间点的具体模型版本生产环境固定快照，并在升级前跑回归 Eval，避免行为无声改变

四、知识、检索与可靠性

术语中文理解实际用途
Hallucination模型生成了没有可靠依据的内容用允许“不知道”、提供可信上下文、先找证据、工具验证等方式降低风险
Grounding让回答以指定证据或实时数据为依据要求来源、引用片段、限制只用提供资料；当前事实可用搜索或数据库工具
Retrieval从资料库找出相关内容先缩小信息范围，再把最相关片段交给模型
RAG检索增强生成检索资料并随请求提供给模型，再让模型基于资料回答
Embedding把内容编码成可比较的数值向量用于语义相似度检索；不是回答本身，也不自动保证资料正确
Vector database存储和搜索向量的数据库按语义相似度查找文档片段，常用于 RAG 的检索层
Knowledge cutoff模型训练知识的大致截止时间不能靠 Prompt 延长；截止后或实时信息需要外部来源
Evidence-first先提取证据，再生成答案把“找依据”和“下结论”分开，便于审计并减少无依据回答

五、工具、工作流与 Agent

术语中文理解实际用途
Tool / Function calling模型选择工具并生成结构化参数宿主程序负责校验、授权、执行，再把结果交回模型；模型本身不直接执行函数
Tool schema工具名称、用途和参数的结构定义帮助模型正确选择工具；应用仍必须验证参数和权限
Prompt chaining把前一步输出传给下一步适合“提取 → 判断 → 写作 → 校验”等可分阶段任务
Aggregation并行获得多个结果后再合并可比较多个候选、来源或评审意见，但成本更高
Agent围绕目标反复规划、调用工具、观察结果并继续行动的系统需要停止条件、权限边界、恢复策略、验收标准和人工确认点
Agent loop计划 → 行动 → 观察 → 更新计划的循环直到完成、无法继续、达到预算，或需要用户决策
Persistence遇到可恢复失败时继续推进不是无限重试；要有重试上限、替代方案和升级条件

六、测试与维护

术语中文理解实际用途
Eval评估模型系统表现的测试集与评分方法固定输入、标准答案或评分量表，用于比较 Prompt、模型和参数
Regression test防止已正确行为在改动后退化每个真实失败样本都可加入回归集
Baseline最小方案的基准成绩没有基线就无法证明复杂 Prompt 是否带来收益
Edge case边界或少见输入最容易暴露规则冲突、格式失败和错误自信
Ceiling effect测试太简单，所有方案都接近满分需要增加困难、边界和真实分布案例，才能区分方案
A/B comparison在相同条件下比较两个版本一次只改一个变量，才能把结果变化归因于该改动
Prompt versioning记录 Prompt 的版本和变更与代码、模型版本和 Eval 结果关联，支持审查、回滚和部署
记忆方法：Prompt 决定“怎么做”，Context 提供“用什么资料做”，Tool 提供“模型本身做不了的动作”，Eval 证明“是否真的做对”。
